# 利用を停止した先生の自動削除の設計書

- 作成日: 2026-11-14
- もとになる設計書: `2026-11-15-teacher-delete-design.md`（削除ボタン。消す中身と規則は、そこで作ったものを使う）
- **ユーザーの決定:** 先生のアカウントの自動消去を作る（前に出した案「停止から 30 日で消す」）。
- **Claude の判断:** この下の作り方すべて（30 日の数え方、いつ・だれの端末で消すか、時計、規則の変え方、見せ方）。

## 1. 動き

- 「利用を停止」したとき、止めた時刻を記録する。**止めてから 30 日たった先生**は、管理者がアプリを開いたときに、自動で削除する（教材・授業の記録・設定・名簿・授業の残り。削除ボタンと同じ中身）。
- サーバーが無いアプリなので、「だれも開いていない間に消える」ことはない。消えるのは、30 日を過ぎたあとに、管理者がアプリ（ホーム、または「先生の管理」）を開いたとき。
- 「再開」すると、記録を消す（数え直し。もう一度止めたら、そこから 30 日）。
- 削除ボタンは、今のまま残す（30 日を待たずに消せる）。
- ログインのためのアカウント（Firebase の Authentication）は、今までどおり消えない。

## 2. 見せ方

- 「先生の管理」の、利用停止中の先生のカードに: 「2026年12月14日に、自動で削除されます（あと 12 日）。」
  - 今日か、もう過ぎている: 「まもなく自動で削除されます。」
  - 止めた時刻の記録が無い（3 章）: 何も出さない。
- 「利用を停止」の確認の文に足す: 「止めてから 30 日たつと、この先生の教材と授業の記録は、自動で削除されます。それまでは「再開」で元に戻せます。」
- 自動で削除したとき: トースト「利用停止から 30 日たった先生 ○ 人を、削除しました。」（「先生の管理」を開いていれば、一覧を読みこみ直す）
- 自動の削除に失敗したとき: 何も出さない（次に開いたときに、もう一度試す）。

## 3. データと規則

- `teacherDirectory/<uid>/suspendedAt`: 止めた時刻（サーバーの時計。`{".sv":"timestamp"}`）。
  - 止める: `teacherList/<uid>: false` と `teacherDirectory/<uid>/suspendedAt` を、1 回の書きこみで。
  - 再開: `teacherList/<uid>: true` と `teacherDirectory/<uid>/suspendedAt: null` を、1 回の書きこみで。
- **止めた時刻の記録が無い停止中の先生**（この機能の前に止めた・古い規則のときに止めた・名簿に行が無い）: 管理者がアプリを開いたとき、その時点を止めた時刻として記録する（そこから 30 日）。名簿に行が無い先生には書けないので、何もしない（自動では消えない。削除ボタンで消す）。
- 規則（`docs/firebase/rules.json`。**先生に貼り直してもらう**）。変えるのは `teacherDirectory.$uid` の 2 行と、下の `teacherList.$uid` の 1 行:

```json
"$uid": {
  ".write": "auth != null && root.child('admins').child(auth.uid).val() === true",
  ".validate": "newData.hasChildren(['email', 'approvedAt']) && newData.child('email').isString() && newData.child('email').val().length <= 254 && newData.child('approvedAt').isNumber() && (!newData.hasChild('suspendedAt') || newData.child('suspendedAt').isNumber())",
  "$other": { ".validate": "$other === 'email' || $other === 'approvedAt' || $other === 'suspendedAt'" }
}
```

- （レビュー round 1 のあとで追加）**止めた時刻が古いまま残らないように、規則で守る。** `teacherList.$uid` の `.validate` も変える（`.write` は変えない）:

```json
".validate": "newData.isBoolean() && (newData.val() === true ? !newData.parent().parent().child('teacherDirectory').child($uid).child('suspendedAt').exists() : (data.val() === false || !newData.parent().parent().child('teacherDirectory').child($uid).exists() || newData.parent().parent().child('teacherDirectory').child($uid).child('suspendedAt').val() === now))"
```

  - 利用中にする（承認・再開）: 同じ書きこみのあとに、止めた時刻が残っていてはいけない（再開は、時刻を消す書きこみといっしょでないと通らない）。
  - 停止にする: 同じ書きこみで、止めた時刻を「今（サーバーの時計）」にしなければ通らない。例外は、もう停止中（`false` を `false` に書く）と、名簿に行が無い先生。
  - これで、「再開のときに時刻を消しそこねた」「止め直したのに古い時刻のまま」は、規則が拒否する（アプリの書きこみが 2 つに分かれて片方だけ成功する、ということが起きない）。
  - 新しい規則のもとでは、アプリの「今までの書きこみでやり直す」は拒否される（名簿に行が無い先生の停止をのぞく）。そのときは、今の失敗の文を出す。
  - 新しい規則を貼ったあと、古い画面のまま（読みこみ直していないタブ）で「利用を停止」「再開」を押すと失敗する。読みこみ直せば動く。
- **古い規則のままの間**は、止めた時刻を書けない。そのとき:
  - 「利用を停止」「再開」は、今までどおり動く（時刻つきの書きこみが拒否されたら、今までの書きこみでやり直す）。
  - 自動の削除は働かない（記録が無いので）。エラーは出さない。

## 4. 時計

- 30 日の判定は、**サーバーの時計**で行う（端末の時計がずれていても、早く消さないため）。
  - 今の時刻: `check/<自分の uid>` にサーバーの時刻を書いて読む（段階 0 の接続確認と同じ場所。規則は今のままで書ける）。
  - これに失敗したら、その回は何も消さない。
- 「あと ○ 日」の表示は、端末の時計でよい（表示だけ）。

## 5. いつ・どう消すか

- きっかけ: 管理者が、ホーム（教材の一覧）か「先生の管理」を開いたとき。1 回の読みこみにつき 1 回。同じタブで続けて何度も走らせない（前の回が終わるまで、次を始めない）。
- 手順: 管理者か確かめる → 名簿と一覧を読む → 記録の無い停止中の先生に、止めた時刻を書く → サーバーの今の時刻を読む → 「止めてから 30 日以上」の先生を、1 人ずつ `repo.deleteTeacher` で消す（今の削除と同じ確かめ: 自分でない・`teacherList` が `false`・授業の持ち主）。
- 消す直前に、その先生の `teacherList` と `suspendedAt` を読み直し、「まだ停止中で、読んだ時刻と同じ」ときだけ消す（開いている間に、別の管理者が再開した・止め直した、をさける）。
- 1 人が失敗しても、ほかの先生は続ける。

## 6. 端の場合

| 場合 | 動き |
|---|---|
| `suspendedAt` が不正（文字・負・0・未来の時刻・`NaN`） | 記録なしとして扱い、今の時刻で書き直す（未来の時刻は「サーバーの今より先」のこと） |
| ちょうど 30 日（境界） | 消す（30 日以上）。1 ミリ秒前は消さない |
| 自分自身・利用中の先生・承認待ちの人 | 消さない |
| 管理者でない先生 | 何もしない（読みこみもしない） |
| 止めて、再開して、また止めた | 最後に止めた時刻から 30 日 |
| 2 人の管理者が同時に開いた・2 つのタブ | どちらかが消す。もう片方は「もう無い」で失敗し、何も出さない |
| 消す対象が 0 人 | 何も出さない |
| 対象が多い（10 人以上） | 1 人ずつ順に。全部終わってから、人数を 1 回だけトーストで出す |
| 通信の失敗・規則が古い・サーバーの時刻が読めない | 何も消さない。何も出さない。次に開いたときに試す |
| 削除の途中で画面を離れた・ログアウトした | 始めていた 1 人ぶんは、1 回の書きこみなので、全部消えるか、何も消えないか。残りはやめる |
| 削除された人が、もう一度ログインした | 「承認待ち」になる（今と同じ） |
| 練習モード | 同じ動き（サーバーの時計の代わりに、練習用の通信の時刻） |

## 7. 知っている限界

- 管理者がアプリを開かないかぎり、消えない。
- この機能の前から停止中の先生は、「管理者が次に開いた日」から 30 日。
- ログインのためのアカウントと、`admins` の行は残る（今と同じ）。
- 新しい規則を貼るまでは、自動の削除は働かない。

## 8. 確かめ方

- 自動テスト: 止める・再開の書きこみ（1 回・時刻つき・古い規則でのやり直し）、30 日の判定（境界・不正な値・サーバーの時計）、消す前の読み直し、自分と利用中を消さない、失敗しても続ける、規則の文字列、画面の文。
- ブラウザ（練習モード）: 止める → カードに日付が出る → 時刻を 31 日前に書きかえて開き直す → 消えてトーストが出る。再開で日付が消える。
- 本物: 先生が規則を貼り直してから、「利用を停止」「再開」が動くこと、カードに日付が出ることを見てもらう。
