# 先生の追加・利用停止の画面の設計書

- 作成日: 2026-11-13
- もとになる設計書: `2026-11-11-classpulse-design.md`（段階 3 の 2 つ目）
- 要件定義書の項目: 4.6・5 章の一部（管理者の招待・利用停止）

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。

## 1. 目的

今は、先生を 1 人増やすたびに、Firebase の画面で「アカウントを作る」「`teacherList` に UID を書く」を手作業でしている。これをアプリの中でできるようにする。使う先生は数人（ユーザーの決定）。

## 2. 入れるもの・入れないもの

### 入れるもの（ユーザーの決定。チャットで案を示して承認）

- 新しい先生が、ログイン画面の「はじめて使う先生はこちら」から、自分のメールアドレスとパスワードで登録する。
- 登録しただけでは使えない。「管理者の先生の承認を待っています」と出る。
- 管理者のアプリに「先生の管理」の画面がある。承認待ちの人のメールアドレスが並び、「承認する」「ことわる」を押せる。
- 「先生の管理」に、使っている先生の一覧が出る。「利用を停止」「再開」を押せる。停止しても、その先生の教材と授業の記録は消えない。
- 自分自身は停止できない。

### 入れないもの（Claude の判断。チャットで説明済み）

- 管理者を増やす画面（管理者は、Firebase の画面で手で登録する）。
- 先生どうしで教材を見せ合う機能。管理者がほかの先生の教材を見る機能。
- メールを送る機能（招待メール、パスワードの再設定メール、メールアドレスの確認）。
- 先生のアカウントそのものの削除（Firebase の画面で行う）。

### してはいけないこと

- パスワードを、データベース・端末の保存・ログ・画面のどこにも残す（今のログインと同じ。保存するのは更新用トークンだけ）。
- 管理者でない人が、`teacherList` を書ける・ほかの人の申しこみやメールアドレスを読める。
- 承認されていない人・停止された人が、先生の画面（教材・授業・履歴）を使える。
- 生徒（匿名のログイン）が、申しこみを書ける。

## 3. データと規則（Claude の判断）

```
admins/<uid>: true                      … 管理者。Firebase の画面で手で書く（アプリからは書けない）
teacherList/<uid>: true | false         … true = 使える、false = 利用停止、無い = 先生でない
teacherDirectory/<uid>: { email, approvedAt }   … 承認したときに管理者が書く（一覧にメールアドレスを出すため）
teacherRequests/<uid>: { email, at }    … 申しこみ。本人が書く。承認・ことわるで消す
```

規則（`docs/firebase/rules.json` に足す・変える。下の `ADMIN` は `auth != null && root.child('admins').child(auth.uid).val() === true`）:

```
"admins": { "$uid": { ".read": "auth != null && auth.uid === $uid" } }

"teacherList": {
  ".read": ADMIN,
  "$uid": {
    ".read": "auth != null && auth.uid === $uid",                    （今のまま）
    ".write": "auth != null && auth.uid !== $uid && root.child('admins').child(auth.uid).val() === true",
    ".validate": "newData.isBoolean()"
  }
}

"teacherDirectory": {
  ".read": ADMIN,
  "$uid": {
    ".write": ADMIN,
    ".validate": "newData.hasChildren(['email', 'approvedAt']) && newData.child('email').isString() && newData.child('email').val().length <= 254 && newData.child('approvedAt').isNumber()",
    "$other": { ".validate": "$other === 'email' || $other === 'approvedAt'" }
  }
}

"teacherRequests": {
  ".read": ADMIN,
  "$uid": {
    ".read": "auth != null && auth.uid === $uid",
    ".write": "auth != null && ((auth.uid === $uid && auth.provider === 'password' && newData.exists() && !root.child('teacherList').child($uid).exists()) || (root.child('admins').child(auth.uid).val() === true && !newData.exists()))",
    ".validate": "newData.hasChildren(['email', 'at']) && newData.child('email').isString() && newData.child('email').val().length <= 254 && newData.child('email').val() === auth.token.email && newData.child('at').val() === now",
    "$other": { ".validate": "$other === 'email' || $other === 'at'" }
  }
}
```

- 申しこみのメールアドレスは、ログインしているアカウントのメールアドレスと同じでなければ書けない（他人のふりをした表示を防ぐ）。
- 本人が申しこみを書けるのは、`teacherList` に自分の行が無いときだけ（停止された人は申しこめない）。
- 承認 = ルートへの 1 回の update: `teacherList/<uid> = true`、`teacherDirectory/<uid> = { email, approvedAt }`、`teacherRequests/<uid> = null`。
- ことわる = `teacherRequests/<uid>` を消す。
- 利用停止 = `teacherList/<uid> = false`。再開 = `true`。
- ほかの規則（`teachers`、`sessions`、`check`）は変えない。これらは `teacherList/<uid> === true` を見ているので、停止（`false`）で使えなくなる。

## 4. 画面

### ログイン画面

- フォームの下に「はじめて使う先生はこちら」のリンク（`#/signup`）。

### 登録の画面（`#/signup`。ログイン不要）

- 見出し「はじめて使う先生の登録」。説明「登録したあと、管理者の先生が承認すると使えるようになります。」
- 入力: メールアドレス、パスワード（8 文字以上）、パスワード（確認）。ボタン「登録する」。「ログイン画面へ戻る」のリンク。
- 入力のまちがい: 「メールアドレスとパスワードを入れてください。」「パスワードは 8 文字以上にしてください。」「パスワードが同じではありません。」
- 失敗: すでに使われているメールアドレス →「このメールアドレスは、もう登録されています。ログイン画面からログインしてください。」／メールアドレスの形が正しくない →「メールアドレスを確かめてください。」／登録が止められている →「いまは登録できません。管理者の先生に知らせてください。」／通信 →「通信できませんでした。接続を確かめて、もう一度押してください。」／ほか →「登録できませんでした。」
- 成功したら、そのアカウントでログインした状態になり、申しこみ（`teacherRequests/<uid>`）を書いて、承認待ちの画面へ進む。申しこみの書きこみに失敗しても承認待ちの画面へ進む（そこで申しこみ直せる）。

### 承認待ちの画面（`#/pending`。ログインしているが、先生として使えない人に出す）

今は、先生でないアカウントでログインすると、ログアウトして「登録されていません」と出している。これを次のように変える。

- 申しこみがある:「（メールアドレス）で登録を申しこみました。管理者の先生の承認を待っています。」ボタン「もう一度確かめる」（承認されていればホームへ進む）、「ログアウト」。
- 申しこみが無い（ことわられた・手で消された・書きこみに失敗した）:「このアカウントは、まだ ClassPulse の先生として登録されていません。」ボタン「利用を申しこむ」、「ログアウト」。
- 利用停止（`teacherList/<uid> === false`）:「このアカウントは、利用を停止されています。管理者の先生に確かめてください。」ボタン「ログアウト」。
- 状態を確かめられない（通信）:「通信できませんでした。」と「もう一度確かめる」。
- 承認待ちの人が先生の画面（`#/`、`#/edit/…` など）を開こうとしたら、この画面へ送る。先生として使える人が `#/pending`・`#/signup` を開いたら、ホームへ送る。

### 先生の管理（`#/teachers`。管理者だけ）

- 左のメニューに「先生の管理」を出すのは、管理者（`admins/<uid> === true`）のときだけ。
- 管理者でない人が開いたら「この画面は、管理者の先生だけが使えます。」
- 「承認待ち」: メールアドレス、申しこんだ日時、ボタン「承認する」「ことわる」。無ければ「承認待ちの人はいません。」
  - 承認の確認: 「（メールアドレス）を承認しますか？」「この人は ClassPulse で教材を作り、授業をできるようになります。知っている先生かどうかを、本人に確かめてから承認してください。」→「承認する」。
  - ことわる確認: 「（メールアドレス）の申しこみをことわりますか？」→「ことわる」。
- 「先生の一覧」: メールアドレス（`teacherDirectory` に無ければ「メールアドレスの記録なし」。自分の行は、ログイン中のメールアドレス）、状態（「利用中」「利用停止中」）、ボタン「利用を停止」「再開」。自分の行には「（自分・管理者）」と出し、ボタンを出さない。
  - 停止の確認: 「（メールアドレス）の利用を停止しますか？」「この先生は ClassPulse を開けなくなります。教材と授業の記録は消えません。あとで「再開」できます。」→「利用を停止」。
  - 発表中の先生を停止すると、その授業は続けられなくなる（規則が拒否する）。確認の文には書かない（数人の運用では、まれ）。README に書く。
- 操作の結果は toast（「承認しました。」「ことわりました。」「利用を停止しました。」「再開しました。」）。失敗は「〜できませんでした。接続を確かめて、もう一度押してください。」

## 5. 練習モード

- 練習モードの先生（demo）は、最初から管理者にする。
- 練習モードでも登録・承認待ち・承認・停止を一通り試せるようにする（別のメールアドレスで登録すると、別の先生になる。パスワードは確かめず、どこにも保存しない）。

## 6. 知っている限界・未確認の前提

- メールアドレスの持ち主かどうかは確かめない。知らない人が、同僚のメールアドレスで登録を申しこむことができる。承認の前に、本人に声をかけて確かめる（確認の文に書く）。承認しても、その人が見られるのは自分の教材だけ。
- 登録の入口はだれでも開ける。関係のない人のメールアドレスが承認待ちに並ぶことがある。
- 未確認: 本物の Firebase で、REST の `accounts:signUp`（メールアドレスとパスワード）が通ること（Firebase の設定で、新しい登録を止めていると通らない）。規則の `auth.provider === 'password'` と `auth.token.email` が、REST で取ったトークンで思ったとおりに働くこと。先生に、2 つ目のアカウントで試してもらう。
- 新しい規則を貼る前でも、新しいアプリは今までどおり動く（管理者かどうかを読めないときは、管理者でないとして扱う）。

## 7. 確かめ方

- 自動テスト: 登録（成功・失敗の種類・パスワードを保存しない）、先生の状態（使える・停止・無い）、申しこみ・承認（1 回の update）・ことわる・停止・再開、管理者かどうか（読めないときは false）、道順、規則の文（管理者だけが書ける・自分の行は書けない・申しこみは本人とメールアドレスの一致）。
- ブラウザ（練習モード）: 別のメールアドレスで登録 → 承認待ち → 先生の画面を開けない → 管理者でログインし直して承認 → その人でログインすると使える → 停止 → 使えない（停止の文）→ 再開。ことわる → 「利用を申しこむ」が出る。管理者でない先生に「先生の管理」が出ない・開けない。
