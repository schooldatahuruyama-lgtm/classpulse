# 教材を作る画面（編集）をスマホで使いやすくする設計書

- 作成日: 2026-11-14
- **ユーザーの決定:** スマホだと操作しづらい。困っているのは「教材を作る画面（編集）」。UI を Codex と相談して良くする。
- **Claude の判断:** この下の案すべて（ユーザーは直し方までは指定していない）。Codex との相談（`.ai-review/20261114-120151_round1.md` の 12 件、`.ai-review/20261114-121040_round2.md` の 4 件）を取り入れた第 3 版。

## 1. 今の状態（幅 375px・高さ 812px で実際に見た）

| # | 困ること | 事実 |
|---|---|---|
| A | 上の帯が高い | `.ed-top` が 4 段に折り返して高さ 210px。キャンバスは画面の上から 270px の所から始まる |
| B | キャンバスが小さい | 余白のため、キャンバスの幅は 311px（画面は 375px） |
| C | 文字が入れにくい | 文字はキャンバスの中の `textarea` に直接入れる。文字は 8〜14px ほど。iPhone の Safari は、16px より小さい入力欄で画面を勝手に拡大する |
| D | 設定にたどり着きにくい | 要素を選んでも何も出ない。「設定」を押すとキャンバスの**下**にパネルが開き、結果を見ながら変えられない |
| E | スライド一覧がキャンバスを押し下げる | 開くと、キャンバスの**上**に高さ約 500px のパネルが出る |
| F | 入力の始め方が分かりにくい | 「選んでいる文字をもう一度タップ」は、小さい説明文にしか書いていない |
| G | 細かく動かしにくい | 指のドラッグだけ |
| H | 要素の上からスクロールできない | 要素はすべて `touch-action: none`。大きい画像の上で画面を送ろうとすると、画像が動いて保存される |
| I | 小さい要素・重なった後ろの要素を選べない | 選ぶ方法はキャンバスのタップだけ |
| J | 資料以外のスライドの入力欄 | 自由記述・ワードクラウドの質問文、動画の URL と題は、右の列（＝開閉するパネルの中）にある。アンケートの選択肢は「番号・入力・削除」の 3 列で、入力欄がせまい |

## 2. 方針

- 変えるのは **幅 899px 以下**（今の「幅 900px 未満」の切りかえを置きかえる。以下「せまい画面」）。幅 900px 以上（iPad の横向き・パソコン）は、見た目も動きも変えない。
- せまい画面かどうかは、CSS は `@media (max-width: 899px)`、JS は `window.matchMedia('(max-width: 899px)')` で見る（関数 1 つにまとめる）。
- 画面に固定するのは、下の帯と下から出るパネルだけ。**文字の入力欄は固定しない**（スマホのキーボードは、固定したものを隠したり、ずらしたりするため）。`visualViewport` は使わない。
- 入力欄の文字は、すべて 16px 以上（勝手な拡大を起こさない）。
- `viewport` の設定（`index.html`）は変えない。

## 3. 作るもの（せまい画面だけ）

### 3.1 上の帯を短くする（A）

- 1 段目: 「←」（読み上げの名前「一覧へ」。44×44px 以上）、教材名の入力欄（のびる。`min-width: 0`）、「発表を開始」。
- 2 段目: 保存の状態。「保存できませんでした」と「もう一度保存」は、折り返してよい（読めて、押せること）。
- 「スライド一覧」「設定」のボタンは、上の帯には出さない（下の帯へ）。

### 3.2 下に固定の帯と、下から出るパネル（D・E）

- 下に固定の帯。ボタン: 「スライド（3／12 枚）」（今何枚目か／全部で何枚）と「設定」。
  - 「設定」は、**資料スライドのときだけ**出す（ほかのスライドは 3.7）。
- それぞれ、左の列（`#ed-left`）・右の列（`#ed-right`）を、**下から出るパネル**として開閉する。同時に開くのは 1 つ。
- パネルの作り: 外わく（見出しと「閉じる」。スクロールしても上に残る）と、中身（描き直す所）を分ける。今の `replaceChildren` での描き直しは、中身だけに行う。
- パネルの高さ: 画面の高さが 600px 以上なら最大 45%、それより低い（横向きのスマホ）なら最大 70%。中は縦にスクロール。低い画面では、キャンバスが隠れてよい（閉じて結果を見る）。
- パネルは幕（モーダル）にしない。開いていてもキャンバスを触れる。フォーカスを閉じこめない。
- フォーカス: ボタンで開いたときだけ、パネルの見出しへ移す。閉じたら、開いたボタンへ戻す。色などを変えて中身を描き直しても、フォーカスとスクロールの位置は動かさない。
- 本文の下に、**帯と、開いているパネルの高さを足したぶん**の余白を取る（中身が短いページでも、最後までスクロールすれば、キャンバスもすぐ使うボタンも隠れない）。帯の下の余白に `env(safe-area-inset-bottom)` を足す。
- 幅が 900px をまたいだら、パネルは閉じた扱いにする。

### 3.3 スライドのパネルの中（E）

- 上から: スライドの一覧（今の横スクロール）、選んでいるスライドの操作（上へ・下へ・複製・削除）、「＋ スライドを追加」。
- 「＋ スライドを追加」を押すと、今の 7 種類のボタンが開く（`aria-expanded`）。もう一度押すと閉じる。
- スライドを選んだ・追加した・複製した → パネルを閉じる（編集にもどる）。上へ・下へ・削除 → 開いたまま。
- スライドが 1 枚も無いときの中央の追加ボタン（今のもの）は、そのまま。

### 3.4 要素を選んだときの「すぐ使うボタン」（D・F）

- 資料スライドのキャンバスのすぐ下に、行を 1 つ:
  - 文字を選んでいる: 「文字を入力」「設定」「選択を外す」
  - 画像・図形を選んでいる: 「設定」「選択を外す」（画面いっぱいの画像を選んだあとでも、選択を外して、画面を送れるようにするため）
  - 何も選んでいない: 説明文「要素をタップして選びます。選んでからドラッグで動かせます。」と、ボタン「要素を選ぶ」（設定のパネルを開く。3.6 の一覧が出る）
- 「削除」は、ここには出さない（すぐ消えて元に戻せないため。設定のパネルの中に、今のまま置く）。

### 3.5 文字は、大きい入力欄で入れる（C）

- 「文字を入力」、または選んでいる文字をもう一度タップで、**キャンバスのすぐ上（ページの流れの中。固定しない）**に入力欄を出す: `textarea`（文字 18px、4 行、中でスクロール）と「できた」。
- 開いている間: 下の帯とパネルを隠す。キャンバスの中には `textarea` を作らない。
- フォーカスは、ボタンを押した（タップした）処理の中で 1 回だけ入れる。あとから勝手に入れ直さない。入力のたびにページを動かさない。
- 打つたびに、キャンバスの文字と「（文字を入力）」の表示だけを書きかえる（要素や入力欄を作り直さない。日本語の変換中も、入力欄の文字と選択のはんいを保つ）。保存は今の `ed.updateItem`。
- 入力は、始めたときのスライドと要素に結びつける。終わるのは: 「できた」、Esc、キャンバスの何もない所・別の要素のタップ、その要素の削除、スライドの切りかえ、画面を離れる、幅が 900px 以上になる。入力欄からフォーカスが外れただけでは終わらない。
- 終わったら、下の帯をもどす。フォーカスは「文字を入力」ボタンへ（Esc・「できた」のとき）。
- 幅 900px 以上は、今のまま（キャンバスの中で入力。フォーカスが外れたら終わる）。

### 3.6 選ぶ・動かす（G・H・I）

- **指とペン（`pointerType` が `mouse` でないもの）で、選んでいない要素に触れたとき:** タップなら選ぶ。なぞったら、ページがスクロールする（要素は動かない）。**動かせるのは、選んでいる要素だけ。** CSS は、選んでいない要素 `touch-action: pan-y pinch-zoom`（ブラウザのふつうのピンチ拡大は止めない）、選んでいる要素と大きさのつまみ `touch-action: none`。マウスは、今のまま（選んでいなくても、すぐ動かせる）。
- **設定のパネル（資料スライド）の上に「要素を選ぶ」の一覧**（せまい画面だけ出す）: キャンバスの要素を、重なりの上から順に 1 行ずつ（高さ 44px 以上）。「文字: （先頭 12 文字）」「文字: （空）」「画像」「図形: 四角」のように出す。押すと、その要素を選ぶ（重なりの順番は変えない）。選んでいる行は `aria-pressed` と「✓」。要素を選んでいるときは折りたたんで出す（`details`）。選んでいないときは開いて出す。
- **設定のパネルに「位置を少し動かす」**（せまい画面だけ出す。文字・画像・図形のどれにも）: 「←」「→」「↑」「↓」の 4 つ（44px 以上。読み上げの名前「左へ」など）。1 回で、スライドの幅・高さの 1%（今の `KEY_STEP`）。端では止まる（今の `clampItem`）。大きさのボタンは作らない。

### 3.7 資料以外のスライド（J）

- アンケート・クイズ・5 段階評価・自由記述・ワードクラウド・動画では、右の列（設定）をパネルにせず、**中央のすぐ下に、いつも開いたまま**出す（ページの流れの中。入力欄がキーボードと当たらない）。下の帯の「設定」は出さない。
- アンケート・クイズの選択肢の行: 入力欄を 1 行いっぱいに。番号は入力欄の左、「削除」（と「正解」）は次の行。

### 3.8 キャンバスの余白（B）

- `.ed-canvas-wrap` の余白を 24px → 16px（キャンバスの幅 311px → 327px）。大きさのつまみ（44px。角から外へ 22px 出る）が、どの角でも画面の中に入る幅を残す。つまみの見た目は変えない。

## 4. 利用者から見える動きの決定（実装の前に知らせること）

- せまい画面で、指とペンでは「**選んでから動かす**」になる（今は、触れてすぐ動かせた）。理由: 要素の上から画面を送れるようにするため。
- せまい画面で、文字の入力は、キャンバスの上の入力欄で行う。
- 要素の削除は、設定のパネルの中だけ（すぐ使うボタンには置かない）。
- iPad の縦向き（幅 768px）も、せまい画面の動きになる。iPad の横向きとパソコンは変わらない。

## 5. 端の場合

| 場合 | 動き |
|---|---|
| 幅が 900px をまたいだ（画面を回した） | パネルを閉じ、文字の入力を終える。入れた文字は残る（打つたびに保存の流れに渡している） |
| パネルを開いたまま、要素の選択が変わった・外れた | 開いたまま、中身だけ変わる。スクロールは上へもどしてよい |
| 設定のパネルを開いたまま、資料以外のスライドへ切りかえた | パネルを閉じる（3.7 の形になる） |
| 文字を入力中に、要素が消えた（削除・別のタブ・スライドの切りかえ） | 入力欄を閉じる。エラーにしない。消えた要素へは書かない |
| とても長い文字・空・改行だけ | 入力欄は中でスクロール。空ならキャンバスに「（文字を入力）」（今と同じ）。文字数の上限は今の決まりのまま |
| 日本語の変換中に打つ | 入力欄を作り直さない。変換が切れない |
| 「←」「↑」などを端で押した・連打した | 端で止まる。1 回ごとに 1 歩。保存は今の自動保存 |
| 指でなぞり始めたが、ブラウザがスクロールにした（`pointercancel`） | 選ばない。動かさない |
| 指で、選んでいる要素をなぞった | 動く（今と同じ）。ページは送られない |
| 要素が 0 個 | 「要素を選ぶ」の一覧に「要素がありません。「文字を追加」などで足してください。」 |
| 要素が上限いっぱい（多い） | 一覧はパネルの中でスクロール |
| スライドが 0 枚 | 下の帯は「スライド（0 枚）」。「設定」は出さない |
| キーボードだけで操作 | 帯・パネル・すぐ使うボタン・入力欄に Tab で行ける。順番は、見た目の順 |
| 練習モードの黄色い帯 | 今のまま上に出る。下の帯・パネルと重ならない |

## 6. 小さくするために、やらないこと

- 元に戻す（Undo）、アプリ独自の拡大（ブラウザのふつうのピンチ拡大は使える）、重なった要素を順に選ぶタップ、大きさを変えるボタン、つまみの見た目の変更、パソコン・iPad 横向きへの展開。

## 7. 確かめ方

- 自動テスト（見た目に関係しない所）: せまい画面の判定、帯の「3／12 枚」、すぐ使うボタンの並び、要素の一覧の名前と順番、位置を動かす計算（端で止まる）、文字の入力の始まりと終わり（要素が消えた・スライドを変えた）、指で選んでいない要素は動かない、マウスは今のまま。
- ブラウザ（練習モード、幅 375×812・812×375・768×1024・1280×800）: A〜J が直っている。幅 900px 以上が変わっていない。
- **本物のスマホで先生に見てもらうこと**（Claude Code は触れない）。iPhone の Safari と Android の Chrome で:
  1. 文字を入力（日本語の変換）→「できた」→ もう一度入力。画面が勝手に拡大しないか。
  2. 画面を回す。
  3. アンケートで、最後の選択肢を足す・消す。クイズで正解を選ぶ。
  4. 大きい画像の上から、画面を上下に送る。
  5. パネルのいちばん下までスクロールして、「閉じる」を押す。
  6. 2 本の指で画面を拡大・縮小できるか（選んでいない要素の上、何もない所）。
