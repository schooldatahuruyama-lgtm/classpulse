# 不適切な言葉の自動チェックと、確かめてから映す機能の設計書

- 作成日: 2026-11-14
- もとになる設計書: `2026-11-11-classpulse-design.md`（段階 2 の残り「投稿の承認・自動検出」）、`2026-11-12-free-text-design.md`、`2026-11-12-word-cloud-design.md`
- 要件定義書の項目: 4.5（72・74・75 行）、305 行（承認のあとに書き直された回答）、327 行（自動の判定を安全の保証として扱わない）

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。

## 1. 目的と前提

- 自由記述・ワードクラウドの回答を教室の画面に映すとき、悪口などが入った回答が、そのまま映らないようにする。
- **ユーザーの決定:** 授業中に先生が使える端末は iPad だけ。その iPad は教室に映っている。
- このため「映す前に、先生だけが全部の回答を読んで承認する」形は作らない（先生が読む時点で、クラス全員に見える。Claude の判断）。代わりに、次の形にする。
  - 自動チェックに当たった回答は「確認待ち」として止め、教室の画面に出さない。件数だけを出す。
  - 先生は、止めた回答を、授業のあとに結果の画面で読める。
  - 授業中に映したいときは、先生が「教室にも映る」と分かったうえで確認待ちの一覧を出し、1 件ずつ「映す」を押す（これが、iPad だけの場合の「確かめてから映す」）。

## 2. 入れるもの・入れないもの

### 入れるもの

- 言葉の一覧（はじめから入っている言葉 ＋ 先生が足した言葉）と、回答との照らし合わせ。
- 先生の設定の画面「止める言葉」（`#/words`）: 自動チェックを使う・使わない、足す言葉。
- 発表の画面: 「確認待ち N 件」の表示、確認待ちの一覧（先生が出したときだけ）、「映す」。
- 授業の結果の画面と CSV: 「自動チェックで止めた回答（言葉）」を分けて出す。

### 入れないもの（理由つき）

- スライドごとの「承認してから映す」設定、別の端末で承認する画面（iPad だけなので使えない）。
- 生徒の端末に「止められた」と知らせること（言いかえて送り直す遊びになる。生徒の画面は今までどおり「送信済み」）。
- はじめから入っている言葉を、1 語ずつ外す設定（必要なら、自動チェックを使わない設定にする）。
- AI や外のサービスでの判定（生徒の文章を外へ送らない）。
- アンケート・クイズの選択肢、教材の文のチェック（先生が書いたもの）。

### してはいけないこと

- 確認待ちの回答の文章・言葉を、先生が一覧を出す前に、発表の画面の DOM に 1 文字でも入れる。
- 確認待ちの一覧を開いている間に、新しく届いた確認待ちの回答・書き直された回答を、その一覧に自動で足す・書きかえる（先生が見ていない文章が、教室に映る）。
- 生徒の uid・言葉の鍵を DOM に入れる（今までの決まりのまま）。
- 生徒の文章を、データベースと先生の端末のほかへ送る。
- 規則（`docs/firebase/rules.json`）を変える（変えなくてよい作りにする）。

## 3. 照らし合わせ（純粋な関数。新しい `js/moderation.js`）

- そろえ方（`normalizeForCheck(text)`）: NFKC にそろえる → 小文字にする → 空白・句読点・記号（Unicode の `\p{P}` `\p{S}` と空白）を取りのぞく。ひらがな・カタカナは変えない（「ばか」を止めると「ばかり」まで止まるため、言葉ごとに形を決める）。長音「ー」は残る。
- 回答をそろえた文字列が、言葉をそろえた文字列を 1 つでもふくめば「当たり」。
- 先生が足す言葉（`normalizeWordList(raw)`）: 文字列だけ。前後の空白を取る。20 文字まで。そろえたあと 2 文字以上（1 文字の言葉は、ほとんどの回答に当たるので捨てる）。そろえた形が同じものは 1 つにする。100 語まで。
- 設定の形: `{ enabled: boolean, words: string[] }`。こわれている・無いときは `{ enabled: true, words: [] }`。
- `createChecker({ enabled, words })` は `(text) => boolean` を返す。`enabled` が `false` なら、いつも `false`。
- はじめから入っている言葉（`BUILTIN_WORDS`。Claude の判断。よく使われる文字の並びに当たらない形だけにした）:

```
死ね 氏ね タヒね しねよ 殺す 殺してや 殺したい ぶっ殺 ころすぞ コロス 消えろ きえろ くたばれ
うざい ウザい ウザイ うぜえ うぜー きもい キモい キモイ きしょい キショい キショイ
バカ 馬鹿 アホ 阿呆 クソ 糞 クズ デブ ブス ハゲ ガイジ キチガイ 気違い
黙れ だまれ うるせえ うるせー ふざけんな てめえ てめー
うんこ ウンコ ちんちん チンチン まんこ マンコ おっぱい オッパイ セックス fuck shit bitch
```

  入れなかった例（ふつうの言葉に当たる）: 「くそ」（やくそく）、「ばか」（ばかり）、「しね」、「カス」（カステラ）、「ゴミ」「いじめ」（授業の話題）、「エロ」（イエロー）、「チンコ」（パチンコ）、「ざこ」（いざこざ）、「殺し」（暗殺した）。

## 4. データ

```
teachers/<uid>/settings/moderation: { enabled: true|false, words: ["…", …] }   … 先生の設定
sessions/<sid>/host/released/<slideId>/<鍵>:
  自由記述: 鍵は生徒の uid、値は「映す」を押したときの文章（文字列）
  ワードクラウド: 鍵は言葉の鍵（hiddenKey）、値は true
teachers/<uid>/history/<sid>/questions[]:
  自由記述: heldTexts: [文…] を足す      … 最後まで確認待ちだった文章
  ワードクラウド: heldWords: [{ word, count }…] を足す
```

- どれも、今の規則で先生本人だけが読み書きできる場所。規則は変えない。
- 回答の分け方（1 件の回答は、どれか 1 つに入る）:
  1. 先生がかくした（`host/hidden`）→ かくした回答（今までどおり）。
  2. 当たりで、「映す」が押されていない → 確認待ち。
  3. それ以外 → 映す回答。
- 自由記述の「映す」は、その文章にだけ効く。`released[uid]` が今の文章と同じときだけ「映す」が効き、生徒が書き直したら、当たりならもう一度確認待ちになる（要件定義書 305 行）。
- ワードクラウドは、言葉（言葉の鍵）ごとに当たりを見る。その鍵の言葉の、どの形（全角・大文字など）が当たっても当たり。
- 件数（`total`、「回答 N 件」）は、確認待ちもふくめて数える（今のかくした回答と同じ）。
- 古い履歴（`heldTexts`・`heldWords` が無い）は、空として読む。

## 5. 先生の端末（host）の動き

- 発表の画面を開いたとき、`repo.getModeration()` で設定を 1 回読む。読めなかったら `{ enabled: true, words: [] }`（止める側にたおす）。授業の途中で設定を変えても、発表の画面を開き直すまで変わらない。
- `host/released` は、開いたときに授業全体の読みこみから 1 回読み、終了のときにもう 1 回読んで、手元のものと合わせる（手元を優先）。
- 状態に `heldCount`（今のスライドが自由記述・ワードクラウドのときの確認待ちの数。それ以外は `null`）を足す。**文章・言葉は状態に入れない。**
- `host.heldItems(slideId)`: その時点の確認待ち。自由記述は `[{ key: uid, text }]`、ワードクラウドは `[{ key, text: 言葉, count }]`。画面が一覧を出すときにだけ呼ぶ。
- `host.release(slideId, key)`: 手元ですぐ「映す」にして `onChange` を呼び（一覧にすぐ出る。0.5 秒の間引きを待たない）、`host/released/…` に書く。書けなかったら、返す Promise を拒否する（手元では映したまま。再試行はしない。読みこみ直すと、もう一度確認待ちになる＝安全な側）。その回答が確認待ちでなければ、何もしないで解決する。授業が終わっている・画面を閉じたときは拒否する。
- 終了のとき、履歴に `heldTexts`・`heldWords` を入れる。`host` を消す今の後片づけで、`released` も消える。

## 6. 画面

### 6.1 発表の画面（教室に映る）

- 自由記述・ワードクラウドのスライドで、確認待ちが 1 つ以上あるとき、右の「回答 N 件 ／ 参加 M 人」の下に「確認待ち 2 件」（ワードクラウドは「確認待ち 2 語」）と、ボタン「確かめる」を出す。0 のときは、どちらも出さない。
- 「確かめる」は、結果を表示している間だけ押せる（表示していない間・切断中・終了の途中・スライドの移動の通信待ちは押せない）。
- 押すと確認: 題「確認待ちの回答を、この画面に出しますか？」、文「自動チェックで止めた回答です。この画面は教室にも映ります。」、ボタン「出す」「やめる」。
- 「出す」で、確認待ちの一覧（`dialog`）を開く。開いた時点の `host.heldItems()` を 1 回だけ読んで出す。
  - 題「確認待ちの回答」。1 件ごとに、文章（ワードクラウドは「言葉 ＋ n 人」）と、ボタン「映す」。下に「とじる」。
  - 「映す」を押すと、その 1 件が一覧から消え、教室の回答の一覧（雲）に出る。保存に失敗したら、トースト「保存できませんでした。読みこみ直すと、もう一度確認待ちになります。」
  - 開いている間に状態が変わったら: 新しい確認待ちは足さない。出している 1 件が、今の確認待ちに同じ鍵・同じ文章で無くなったら（書き直した・かくした・映した）、その 1 件を消す。文章を書きかえて出し直すことはしない。
  - 全部なくなったら「確認待ちの回答はありません。」
  - スライドが変わった・結果をかくした・授業の終了を始めた・画面を離れたら、一覧を閉じる。
- 「映す」を押さなかった回答は、確認待ちのまま（何もしなければ、教室には出ない）。

### 6.2 授業の結果の画面・CSV

- 自由記述: 「授業中にかくした回答」のあとに、あるときだけ「自動チェックで止めた回答（授業では映していません）」。
- ワードクラウド: 同じ場所に「自動チェックで止めた言葉（授業では映していません）」。
- 表示した回答が 0 件で、かくした・止めた回答があるときの文は、今の「表示した回答はありません。」を使う。
- CSV: かくした回答の行のあとに、あるときだけ、`自動チェックで止めた回答` の行と文章（ワードクラウドは `自動チェックで止めた言葉` の行と、言葉・人数）。式にしない処理は今までどおり。

### 6.3 設定の画面「止める言葉」（`#/words`。先生だけ）

- 入口: ホームの上のナビゲーションに「止める言葉」（ゴミ箱などと同じ並び）。
- 説明: 「自由記述とワードクラウドで、下の言葉が入った回答は、教室の画面に出さずに止めます。止めた回答は、授業中に確かめて映すことも、授業のあとに結果の画面で読むこともできます。」「自動チェックは、すべての不適切な回答を見つけられるわけではありません。」
- チェックボックス「不適切な言葉の自動チェックを使う」（はじめは入っている）。
- 入力欄（複数行）「足す言葉（1 行に 1 つ）」。保存のとき `normalizeWordList` で正す。捨てたもの（1 文字、21 文字以上、100 語をこえた分）があれば「使えない言葉を n 個はずしました。」と出す。
- 折りたたみ「はじめから入っている言葉を見る」（`details`。閉じた状態で出す）。
- 「保存」。成功「保存しました。次に発表の画面を開いたときから使われます。」、失敗「保存できませんでした。接続を確かめて、もう一度押してください。」
- 読みこめなかったときは、今までの画面と同じ「読みこめませんでした。」と「もう一度」。

## 7. 知っている限界

- 言葉の一覧に無い言い方・当て字・わざと文字をはさんだ書き方は止められない。逆に、ふつうの言葉の一部が当たって止まることがある（例: 「バカンス」「デブリ」）。自動チェックは目安で、安全の保証ではない。
- 確認待ちの一覧を出すと、その文章は教室に映る。映したくないときは、先に iPad の画面の共有を止める（手順書に書く）。
- 「映す」の保存に失敗したまま発表の画面を読みこみ直すと、その回答は確認待ちに戻る。
- 設定は、発表の画面を開いたときに読む。授業の途中で変えた設定は、開き直すまで使われない。
- 2 つの端末で同じ授業の発表の画面を開いた場合、片方の「映す」は、もう片方には開き直すまで伝わらない。

## 8. 確かめ方

- 自動テスト: そろえ方（全角・大文字・間の空白や記号）、当たる例・当たらない例（「やくそく」「ばかり」「イエロー」「パチンコ」「暗殺した」は当たらない）、先生の言葉の正し方、使わない設定、回答の 3 つの分け方、書き直したら確認待ちに戻る、ワードクラウドの言葉ごとの判定、件数、履歴（`heldTexts`・`heldWords`、uid や鍵が入らない、古い履歴）、CSV、host（設定を読めないとき、`release` の成功・失敗、状態に文章が入らない、終了のときの合わせ方）、発表の画面（一覧を出す前の DOM に文章が無い、開いている間に新しいものを足さない）。
- ブラウザ（練習モード。先生のタブ 1 つ、生徒のタブ 2 つ）: 当たる文章と当たらない文章を送る → 当たらないものだけ映る・「確認待ち 1 件」 → 確かめる → 映す → 一覧に出る → 書き直して確認待ちに戻る → 終了 → 結果と CSV。設定の画面で言葉を足して、次の授業で止まること。
- 本物の Firebase・iPad は、先生が試す。規則の貼り直しは、いらない。
