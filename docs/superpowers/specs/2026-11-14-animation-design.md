# アニメーションの設計書

- 作成日: 2026-11-14
- もとになる要件: 要件定義書 40 行目「基本的なアニメーションを対象とする。フェード、順番表示、基本的な切り替え効果などの具体的な対応表は実装前に確定する。」244 行目「過度な点滅・装飾アニメーションを避ける。」
- **ユーザーの決定:** アニメーションを作る（段階 4 で見送っていたもの）。
- **Claude の判断:** この下の対応表と作り方すべて。

## 1. 対応表（作るもの・作らないもの）

| 種類 | 作る | 中身 |
|---|---|---|
| 順番表示 | ○ | 資料スライドの要素（文字・画像・図形）を、「次へ」を押すたびに順に出す |
| フェード | ○ | 順に出る要素は、ふわっと出る（0.3 秒）。効果は、この 1 種類だけ |
| 切り替え効果 | ○ | スライドが変わるとき、新しいスライドがふわっと出る（0.25 秒）。すべての教材で、いつも同じ。設定は無い |
| 動く・回る・飛びこむ・消える効果、効果の種類や速さを選ぶ、音、自動で進む | × | 作らない |
| PowerPoint のアニメーションの取りこみ | × | 作らない |
| アンケート・クイズなどのスライドの中の順番表示 | × | 作らない |

- 端末の「視差効果を減らす」（`prefers-reduced-motion: reduce`）のときは、どれも動かさず、すぐ出す。

## 2. データ

- 資料スライドの要素に `step`（0 以上 20 以下の整数）を足す。`0`・無い・不正な値は「最初から出ている」。`1` 以上は「次へ」で出る順番。
- 同じ `step` の要素は、いっしょに出る。
- 出す回数は、番号をつめて数える: そのスライドにある 1 以上の `step` の種類を小さい順に並べ、1 回目・2 回目…とする（`step` が 1 と 3 だけなら、2 回で全部出る）。
- 授業の中の今の場所 `sessions/<sid>/pub/current` に `step`（これまでに出した回数。0 以上の整数）を足す。Firebase の規則は変えない（`pub` は授業の持ち主だけが書ける。今の規則で足りる）。

## 3. 教材を作る画面

- 資料スライドで要素を選ぶと、設定に「出る順番」: 「最初から出す」か、「順番 3（「次へ」の 2 回目で出る）」。前の数は「−」「＋」で変える番号（0 が「最初から出す」。上は 20）、後ろの数は、つめた後の本当に出る回。どの幅でも出す。
- キャンバスでは、すべての要素を見せる（隠さない）。順番のある要素には、左上に小さい番号の印（例「2」。つめた後の回数）を付ける。印は編集画面だけ。
- 縮小表示・授業の記録・発表を始める前の見本は、すべての要素を見せる。
- 複製したスライド・要素は、順番も写る。「元に戻す」で戻せる（ふつうの変更）。

## 4. 発表の画面（先生）

- 資料スライドに来たとき、順番のある要素は隠れている（場所は取らない。重なりは今のまま）。
- 「次へ」（ボタン・キー）: まだ出していない回があれば、次の 1 回ぶんを出す（スライドは変わらない）。全部出ていれば、次のスライドへ。
- 「前へ」: 1 回ぶん以上出していれば、最後の 1 回ぶんを隠す。何も出していなければ、前のスライドへ行き、**そのスライドは全部出た状態**にする。
- スライドの番号のそばに、順番があるスライドだけ「出す 1／3」と出す。
- 最後のスライドで、まだ出していない回があるときの「次へ」は、出すだけ（授業は終わらない。今の最後のスライドの動きは変えない）。
- 「前へ」「次へ」のほかの方法で別のスライドへ移ったとき（あれば）は、何も出していない状態から。

## 5. 生徒の画面

- 資料スライドは、先生と同じ回数まで出す（`pub.current.step`）。出るときはフェード。
- `pub.current.step` が無い・数でない（古い画面の先生から届いた）ときは、**全部出す**（隠れたままにしない）。
- 途中から参加した・つなぎ直した: 今の回数までを、フェードなしですぐ出す。

## 6. 端の場合

| 場合 | 動き |
|---|---|
| `step` が不正（文字・小数・負・21 以上・`NaN`） | 読みこむとき 0 に正す（小数は切り捨て、21 以上は 20、負と数でないものは 0） |
| 「＋」を 20 で・「−」を 0 で押す | 止まる。ボタンは押せない（`disabled`） |
| 番号がとんでいる（1 と 3）・重複（同じ番号が 2 つ） | つめて 2 回／同じ回にいっしょに出る |
| 順番のある要素が 0 個 | 今までと同じ動き（「次へ」で次のスライド）。「出す ○／○」は出さない |
| 全部の要素に順番がある | 来たときは白いスライド。「次へ」で順に出る |
| 発表中に `pub.current.step` が、そのスライドの回数より大きい・負 | 0〜回数の間に正して扱う |
| 「次へ」の連打・通信待ち | 今の直列の処理のまま。1 回ごとに 1 つ進む |
| 通信が切れて、つなぎ直した | 今の回数をそのまま出す（フェードなし） |
| 先生が発表の画面を読みこみ直した | `pub.current.step` から続ける |
| 質問のスライド（アンケートなど）から資料スライドへ「前へ」 | 全部出た状態 |
| 質問の締め切り（次のスライドへ進むと締め切る） | 資料スライドの中で出すだけのときは、何も締め切らない（質問のスライドには順番表示が無いので、今の決まりのまま） |
| フェードの途中で次を押した | 前の要素はすぐ出し終え、次がフェードで出る。こわれない |
| 結果の更新などで、同じスライドを描き直した | フェードをやり直さない（スライドや回数が変わったときだけ） |
| `prefers-reduced-motion: reduce` | フェードも切り替え効果も無し |
| 違反の見せ方 | 不正な `step` は黙って正す（教材はこわれない。編集画面に出るのは正した後の値） |

## 7. 確かめ方

- 自動テスト: `step` を正す、回数をつめる、ある回数で見える要素、「次へ」「前へ」の行き先（途中・端・前のスライドは全部出た状態）、不正な `pub.current.step`、生徒側の「無いときは全部出す」。
- ブラウザ（練習モード）: 編集で順番を付ける → 発表で順に出る・戻る → 生徒の画面（別のタブ）が同じ回数になる。
- 本物の iPad と生徒の端末での見え方（フェードのなめらかさ）は、先生に見てもらう。
