# 教材のゴミ箱と復元の設計書

- 作成日: 2026-11-13
- もとになる設計書: `2026-11-11-classpulse-design.md`（段階 3 の 1 つ目）
- 要件定義書の項目: 4.6 の一部（ゴミ箱と 30 日の復元）

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。

## 1. 目的

まちがって消した教材を、30 日以内なら元に戻せるようにする。

## 2. 入れるもの・入れないもの

### 入れるもの（ユーザーの決定。チャットで案を示し、「ないです」で承認）

- ゴミ箱に入るのは教材だけ。授業の記録は、今までどおり「削除」で完全に消える。
- 教材の一覧の「削除」は、教材をゴミ箱に移す。確認の文は「ゴミ箱に移しますか？ 30 日間は元に戻せます」。
- ゴミ箱の画面（`#/trash`）。教材の名前・スライドの枚数・消した日・あと何日で消えるかが並ぶ。
- ゴミ箱の教材ごとに「元に戻す」「完全に削除」（確認あり）。
- 「ゴミ箱を空にする」（確認あり）。
- ゴミ箱に入れてから 30 日たった教材は、自動で完全に消える。
- ゴミ箱の中の教材は、編集も発表もできない。

### 入れないもの

- 授業の記録のゴミ箱。
- 30 日の日数を変える設定。
- 裏で動く自動の掃除（このアプリにはサーバーの処理が無い）。

### してはいけないこと

- Firebase の規則を変える（`teachers/<uid>` の下だけを使う）。
- ゴミ箱に移す・戻すために、教材の中身（画像を含む。最大 5MB）を読み書きする。
- ゴミ箱に無い教材の見え方・保存のしかたを変える。

## 3. データ（Claude の判断）

- 教材の中身（`teachers/<uid>/decks/<id>`）は動かさない。
- 一覧の項目に印を付ける: `teachers/<uid>/deckIndex/<id>/deletedAt = ゴミ箱に入れた時刻（ミリ秒）`。
  - 印がある項目は、教材の一覧に出さず、ゴミ箱に出す。
  - 元に戻す = 印を消す。完全に削除 = 今までの削除（`decks/<id>` と `deckIndex/<id>` を 1 回の update で消す）。
- 教材の保存（`saveDeck`）は、一覧の項目をまるごと書かず、`title`・`updatedAt`・`slideCount` を 1 つずつ書く。別のタブの編集画面が保存しても、ゴミ箱の印が消えないようにするため。
- `loadDeck` は、ゴミ箱の印がある教材では `null` を返す（編集画面は「見つかりません」、発表の開始は「この教材が見つかりません」になる）。印の確認は小さな読みこみ 1 回で、教材の読みこみと並べて行う。
- 30 日の判定: `deletedAt` が数で、`今 − deletedAt ≥ 30 日`。`deletedAt` が数でない・未来の時刻のものは、自動では消さない（ゴミ箱には出す。残りは 30 日と出す）。
- 自動で消すのは、先生が授業ダッシュボードかゴミ箱を開いたとき。失敗しても画面には出さず、次に開いたときにやり直す。
- 日数は `CONFIG.trash.keepDays = 30`。

## 4. 画面

- 左のメニューに「ゴミ箱」を足す。
- 教材の一覧で「削除」→ 確認「この教材をゴミ箱に移しますか？」「「〇〇」をゴミ箱に移します。30 日間は、ゴミ箱から元に戻せます。授業の記録は残ります。」→「ゴミ箱に移す」。終わったら「ゴミ箱に移しました。」。
- ゴミ箱の画面:
  - 見出し「ゴミ箱」、説明「ゴミ箱に入れてから 30 日たった教材は、自動で完全に削除されます。」
  - 空のとき「ゴミ箱は空です。」
  - 教材ごと: 名前、「スライド n 枚 ・ yyyy年m月d日 にゴミ箱へ ・ あと n 日で完全に削除」（残り 0 日は「まもなく完全に削除」）、ボタン「元に戻す」「完全に削除」。
  - 「完全に削除」の確認: 「この教材を完全に削除しますか？」「「〇〇」を完全に削除します。元に戻せません。授業の記録は残ります。」
  - 「ゴミ箱を空にする」の確認: 「ゴミ箱を空にしますか？」「ゴミ箱の教材 n 個を完全に削除します。元に戻せません。」
  - 失敗したとき: 「〜できませんでした。接続を確かめて、もう一度押してください。」

## 5. 編集画面の「画面を離れたあとの保存」との関係（Claude の判断）

- ゴミ箱に移すときも、今の削除と同じ手続き（`deleting`）を使う: 進行中の保存が済むのを待ってから移し、このタブでは「削除済み」の印を付けて、それより後は書かない。まだ保存できていなかった変更（通信できずに再試行を待っていたもの）は捨てる（今の削除と同じ）。
- 元に戻したら、このタブの「削除済み」の印を外す（`undelete`）。外さないと、戻した教材をこのタブで開けない。

## 6. 知っている限界

- 端末の時計が大きく進んでいると、30 日より早く消えることがある（時刻は端末の時計で比べる）。
- 別のタブで編集中の教材をゴミ箱に移すと、そのタブの保存は続く（中身は書かれるが、ゴミ箱に入ったまま）。完全に削除したあとにそのタブが保存すると、教材が作り直される（今の削除と同じ）。
- ゴミ箱の教材も、Firebase の保存量（1GB）に数えられる。

## 7. 確かめ方

- 自動テスト: 一覧とゴミ箱の出し分け、移す・戻す・完全に削除・空にする・30 日の自動削除（29 日は残る、30 日は消える、数でない・未来の時刻は残る）、保存しても印が消えない、ゴミ箱の教材は `loadDeck` が `null`、残りの日数、道順（`#/trash`）、`undelete`。
- ブラウザ（練習モード）: 移す → 一覧から消えてゴミ箱に出る → 編集の URL を直接開くと「見つかりません」→ 戻す → 一覧に戻り、中身がそのままで、編集できる → もう一度移して完全に削除 → どこにも無い。空にする。データを手で書きかえて 31 日前にすると、開いたときに消える。授業の記録は残る。
