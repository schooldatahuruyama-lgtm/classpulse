# 授業の結果の書き出し（CSV・Google Drive）の設計書

- 作成日: 2026-11-13
- もとになる設計書: `2026-11-11-classpulse-design.md`（段階 2 の残り「CSV 出力」と、段階 3 の 4 つ目「Google Drive 連携」）、`2026-11-13-google-login-design.md`（Google への移動と戻りのしくみ）
- 要件定義書の項目: 4.7 の一部

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。先生は「Google Drive 連携に進む」「質問はいらないので任せる」と決めた。**下の中身は、すべて Claude の判断である。**

## 1. 目的

授業の結果を、先生の手元に残せるようにする。授業のあとに、表として見直す・ほかの資料に貼る・保管する、という使い方ができる。

## 2. 入れるもの・入れないもの

### 入れるもの

- 授業の結果の画面（`#/history/<sid>`）に、ボタンを 2 つ足す。
  - 「CSV をダウンロード」: 結果を CSV ファイルとして端末に保存する。Google の設定がいらない。
  - 「Google ドライブに保存」: 結果を Google スプレッドシートとして、先生の Drive に作る。作ったあと、開くためのリンクを出す。
- 書き出す中身は、結果の画面に出ているものと同じ（授業の名前・日時・参加人数、質問ごとの集計、自由記述の文章、ワードクラウドの言葉と人数、クイズの正解と正答率、評価の平均、授業中にかくした回答）。

### 入れないもの（理由つき）

- Drive の中のファイルを、アプリの中から選んで取りこむ機能。Drive 全体を読む権限（Google の審査が必要）か、Google の外部スクリプト（このアプリは読みこまない決まり）が要るため。Drive にある PDF は、今ある「PDF から作る」のファイルを選ぶ画面から選べる（iPad の「ファイル」に Google Drive を足してある場合・パソコンに Drive のアプリを入れてある場合）。
- 教材の控えを Drive に取る機能。ゴミ箱と復元で、まちがって消したときの備えはできている。必要になったら別に設計する。
- Excel・PDF の形式での書き出し（スプレッドシートと CSV から、先生が自分で変えられる）。
- すべての授業をまとめて書き出す機能。授業が終わったときに自動で保存する機能。

### してはいけないこと

- 外部のスクリプトを読みこむ。
- Google のアクセストークンを、`localStorage`・`sessionStorage`・URL・履歴・ログに残す（メモリの中だけに置き、ページを閉じたら消える）。
- Drive の、このアプリが作ったファイル以外を読む・書く権限を求める（求める権限は `https://www.googleapis.com/auth/drive.file` だけ）。
- 生徒の書いた文章を、表計算ソフトが式として実行する形で書き出す（下の 4 章）。
- クライアント ID が空・練習モードのときに、Drive のボタンを出す。

## 3. Drive へ保存するしくみ

1. 「Google ドライブに保存」を押す。メモリにアクセストークンがあり、期限まで 1 分以上あれば、4 へ。
2. 無ければ、`state`（乱数）を作り、`sessionStorage` の `classpulse:drive-export` に `{ state, sid, at }` を入れて、次の URL へページごと移る:
   `https://accounts.google.com/o/oauth2/v2/auth?client_id=<クライアント ID>&redirect_uri=<戻る場所>&response_type=token&scope=https%3A%2F%2Fwww.googleapis.com%2Fauth%2Fdrive.file&state=<state>&include_granted_scopes=true`（ログイン中のメールアドレスがあれば `login_hint` に入れる）。戻る場所は、Google ログインと同じ（`origin + pathname`）。
3. Google が `#access_token=…&token_type=Bearer&expires_in=…&state=…`（失敗なら `#error=…&state=…`）で戻す。アプリの起動時（Google ログインの戻りの処理と同じ場所。先に `state` の保存を見て、どちらの戻りかを決める）に:
   - まず、ハッシュを置きかえる（保存に `sid` があれば `#/history/<sid>`、無ければ `#/history`）。トークンを URL と履歴に残さない。
   - `sessionStorage` の保存を取り出して、すぐ消す。保存があり、10 分以内で、`state` が同じときだけ、トークンをメモリに置く（`expires_in` から期限を計算）。「この授業を、戻ったらすぐ保存する」という印（`sid`）も、メモリに 1 回分だけ置く。
   - 合わないときは、トークンを捨てる。結果の画面に「Google ドライブへの保存を確かめられませんでした。もう一度ためしてください。」と出す。利用者がやめた（`access_denied`）ときは「Google ドライブへの保存をやめました。」
4. 結果の画面が、その授業の印があるのを見つけたら（または、トークンがあってボタンが押されたら）、アップロードする。印は使ったら消す（読みこみ直しで 2 回作らない）。
   - `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart&fields=id,webViewLink`、`Authorization: Bearer <トークン>`。
   - 本文は `multipart/related`: 1 つ目が JSON `{ "name": "<ファイル名>", "mimeType": "application/vnd.google-apps.spreadsheet" }`、2 つ目が `text/csv; charset=UTF-8` の CSV。こうすると、Drive がスプレッドシートに変えて保存する。
   - ファイル名: `ClassPulse_<授業の名前>_<YYYY-MM-DD>`（授業の名前は 60 文字まで。終了の日付）。
5. 成功: 「Google ドライブに保存しました。」と、リンク「スプレッドシートを開く」（`webViewLink`。別のタブで開く。`rel="noopener"`）。
6. 失敗の文:
   - 401（トークンが無効）→ トークンを捨てて「Google の確認が切れました。もう一度「Google ドライブに保存」を押してください。」
   - 403 →「Google ドライブに保存できませんでした。Drive の設定（Google Drive API）が有効になっているか、管理者の先生に確かめてください。」
   - 通信 →「通信できませんでした。接続を確かめて、もう一度押してください。」
   - ほか →「Google ドライブに保存できませんでした。」
- Drive に使う Google アカウントは、ログインのアカウントと同じでなくてよい（パスワードでログインしている先生も使える）。

## 4. CSV の中身

- 文字コードは UTF-8。ダウンロードのときは、先頭に BOM を付ける（Excel で文字が化けないように）。Drive へ送るときは付けない。行の区切りは CRLF。
- 値に `,`・`"`・改行があれば `"` で囲み、`"` は `""` にする。
- **式にしない:** 値が `=`・`+`・`-`・`@`・タブ・復帰（CR）で始まるとき（前の空白を除いて見る）は、先頭に `'` を付ける（生徒が書いた `=HYPERLINK(...)` のような文章を、表計算ソフトが実行しないように）。数として書く値（人数・割合・平均）には付けない。
- 並び:

```
ClassPulse 授業の結果
授業の名前,<名前>
開始,<YYYY-MM-DD HH:MM>          … 開始の時刻が無ければ、この行を出さない
終了,<YYYY-MM-DD HH:MM>
参加人数,<n>
（空行）
質問 1,<種類>,<質問文>            … 種類: アンケート / 自由記述 / ワードクラウド / クイズ / 5 段階評価
…その質問の表…
回答,<人数または件数>
（空行）
質問 2,…
```

- アンケート: 見出し行 `選択肢,人数,割合(%)`、選択肢ごとに 1 行（割合は小数 1 けた。回答 0 人なら 0）。
- クイズ: 見出し行 `選択肢,人数,割合(%),正解`、正解の行の 4 列目に `○`。そのあと `正答率(%),<小数 1 けた>`（正解の記録が無ければ `正解,記録なし`）。
- 5 段階評価: 見出し行 `評価,人数,割合(%)`、`1`〜`5` の 5 行（1 と 5 の行は、両はしの言葉があれば `1（むずかしい）` のように付ける）。そのあと `平均,<小数 2 けた>`（回答 0 人なら `平均,`）。
- 自由記述: 見出し行 `回答`、文章ごとに 1 行。かくした回答があれば、空行なしで `授業中にかくした回答` の行のあとに、文章ごとに 1 行。
- ワードクラウド: 見出し行 `言葉,人数`、言葉ごとに 1 行。かくした言葉があれば `授業中にかくした言葉` の行のあとに同じ形で。
- 時刻は、端末の時刻（今の画面の出し方と同じ考え方）。
- 履歴の値がこわれていても（配列でない、数でない）、例外を投げず、空・0 として書く（今の `repo.getHistory` が正した形を受け取る）。

## 5. 画面

- 結果の画面の、見出しと参加人数の下に、ボタンの行: 「CSV をダウンロード」「Google ドライブに保存」（Drive は、クライアント ID があり練習モードでないときだけ）。
- その下に、知らせの場所（成功のリンク、失敗の文。`role="status"`／失敗は `role="alert"`）。
- Drive へ保存している間は「保存しています…」と出し、2 つのボタンを押せなくする。
- CSV のファイル名: `ClassPulse_<授業の名前>_<YYYY-MM-DD>.csv`（ファイル名に使えない文字 `\ / : * ? " < > |` と制御文字は `_` に変える）。

## 6. 先生の設定（1 回だけ。手順書に書く）

- Google Cloud の「API とサービス」→「ライブラリ」で「Google Drive API」を有効にする。
- それ以外（クライアント ID、戻ってよい場所）は、Google ログインの設定のまま使う。規則は変えない。

## 7. 知っている限界・未確認の前提

- 未確認（先生の設定のあとに、先生が試す）: Google がアクセストークンを URL で返す流れが、このクライアント ID で通ること。`drive.file` の権限で、CSV をスプレッドシートに変えて保存できること。iPad での動き。
- Google の同意画面に「Google ドライブの、このアプリで使用する特定のファイルのみの参照、編集、作成、削除」という許可が出る。先生が「許可」を押す必要がある。
- 学校・自治体のアカウントは、管理している人が Drive への外のアプリのアクセスを止めていると使えない。そのときは CSV のダウンロードを使う。
- Drive へ保存するとき、ページごと Google へ移って戻る（結果の画面は読みこみ直しになる）。
- 同じ授業を 2 回保存すると、スプレッドシートが 2 つできる（上書きはしない）。
- 保存したスプレッドシートには、生徒の書いた文章がふくまれる（名前は付いていない）。置き場所と共有は、先生の Drive の設定による（作ったときは、先生だけが見られる）。

## 8. 確かめ方

- 自動テスト: CSV の中身（5 種類の質問、かくした回答、0 人、正解の記録なし、`,` `"` 改行の入った文章、式になりそうな文章に `'` が付く・数には付かない、BOM の有無）、ファイル名、認可の URL、戻りの読み取りと判定（成功・やめた・`state` ちがい・時間切れ・保存なし）、ハッシュの置きかえが先、トークンが保存に残らない、アップロードの送る中身（URL・ヘッダー・2 つの部分）、失敗の種類、Google ログインの戻りと取りちがえない（どちらの保存も無い `#error=` は、今までどおりログインの失敗として扱う）。
- ブラウザ（練習モード）: CSV をダウンロードでき、中身が画面と同じ。Drive のボタンが出ない。結果の画面の今までの動き（削除など）が変わらない。
- 本物: 先生が「Google Drive API」を有効にしたあとに試す。
