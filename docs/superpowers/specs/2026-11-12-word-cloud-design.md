# ワードクラウドの設計書（段階 2 の 3 回目）

- 作成日: 2026-11-12
- もとになる設計書: `2026-11-11-classpulse-design.md`（全体設計）、`2026-11-12-free-text-design.md`（自由記述。以下「自由記述の設計」）
- 要件定義書の項目: 4.2 のワードクラウド、4.4 の匿名、4.5 の一部（非表示）

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。

## 1. 目的

生徒から短い言葉を集め、多くの人が書いた言葉ほど大きく、教室の画面に映す（ユーザーの決定）。1 人がいくつか送れる（ユーザーの決定）。

進行の規則（次へ進むと締切、締切は開け直さない、「結果を表示」を押すまで映さない）と、匿名・非表示の考え方は、自由記述と同じにする。

## 2. 入れるもの・入れないもの

### 入れるもの

- スライドの種類「ワードクラウド」。質問文だけを持つ。
- 生徒: 入力欄 3 つと「送信」。1 人 3 つまで（Claude の判断）。1 つ 20 文字まで（Claude の判断）。締切前なら書き直して送り直せる。
- 先生（教室に映る画面）: 書いている間は「回答 n 人 / 参加 m 人」だけ。「結果を表示」で言葉の雲。言葉をタップすると、人数と「かくす」。
- 授業の結果の画面: 言葉と人数の一覧。

### 入れないもの

- 文章を単語に分けること（日本語の分かち書きはしない。送られた 1 つを 1 語として扱う）。
- 生徒の端末に、ほかの生徒の言葉を出すこと。
- 言葉をきれいに敷きつめる配置（らせん状の配置など）。大きさのちがう言葉を、折り返して並べる形にする（Claude の判断: 読みやすさと軽さを優先）。
- 映す前の承認、不適切な言葉の自動検出、名前つきの回答。

### してはいけないこと

- 「結果を表示」の前に、先生の画面へ言葉を 1 文字でも出す。
- 言葉に、生徒の名前や端末の匿名 ID を付けて画面に出す・履歴に残す。
- 生徒の言葉を `pub` に書く（生徒の端末へ届ける）。
- 締切済みの質問の受付を再開する。

## 3. 画面

### 3.1 スライド編集

スライドを追加する所に「ワードクラウド」を足す。編集できるのは質問文だけ。扱いは自由記述と同じ（空の質問文の知らせ、縮小表示とキャンバスの見本）。

### 3.2 生徒の画面

- 質問文、入力欄 3 つ（1 行。それぞれ 20 文字まで）、「送信」。
- 空の欄は送らない。3 つとも空（空白だけ）なら送れない。同じ言葉を 2 つ書いたら 1 つにまとめる（4.3 の「同じ言葉」の決まりで）。
- 送信状態の表示、「送り直す」、一時停止・締切のときの読み取り専用、書きかけの一時保存は、自由記述と同じ。
- 結果を表示中は「みんなの回答は、前の画面を見てください」と出す。

### 3.3 先生の発表画面（教室に映る）

- 表示する前: 質問文と「回答 n 人 / 参加 m 人」。言葉は出さない（DOM に作らない）。
- 表示中: 言葉を、人数に応じた文字の大きさで、中央に折り返して並べる。いちばん多い言葉がいちばん大きい。全員が 1 人ずつなら、同じ大きさ。並びは、大きい言葉が 1 か所に固まらないよう、言葉から決まる順（表示のたびに変わらないこと）。
- 言葉の種類が多いときは、人数の多い順に 60 語までを出し、「ほか n 語」と出す。
- 届くたびに反映する（0.5 秒に 1 回まで）。
- 言葉をタップすると、小さな確認を出す: 「『〇〇』 3 人」と、「かくす」「とじる」。「かくす」で、その言葉が雲から消える。授業中は元に戻せない。あとから同じ言葉が届いても出さない（かくす対象は言葉）。
- 「結果をかくす」、一時停止・再開、前へ・次へ、授業の終了は、自由記述と同じ。

### 3.4 授業の結果（履歴）

質問ごとに、回答した人数と、言葉と人数の一覧（人数の多い順）。授業中にかくした言葉は「授業中にかくした言葉」と分けて出す。

## 4. データ

### 4.1 構造

```
decks/<教材ID>/slides/<スライドID>/  type: "cloud", question
sessions/<授業ID>/
  pub/polls/<スライドID>/  status, resultsVisible（最初は false）
  inbox/answers/<スライドID>/<生徒のuid>: { words: [言葉, ...（1〜3 個）], at }
  host/hidden/<スライドID>/<言葉の鍵>: true      … 自由記述と同じ場所。自由記述では uid、ワードクラウドでは言葉の鍵
history/<授業ID>/questions[]:
  { slideId, type:"cloud", question, words:[{ word, count }], hiddenWords:[{ word, count }], total }
```

- `total` は、回答した人数（1 つ以上の正しい言葉を送った生徒の数）。
- `words` はデータベースでは `0`・`1`・`2` の鍵を持つ形になる。読むときは配列に正す。

### 4.2 規則（`docs/firebase/rules.json`）

`inbox/answers/<スライドID>/<uid>` の検証に、3 つ目の場合を足す。書きこみの条件は変えない。

- 授業の写しのスライドの `type` が `cloud` のとき: `words` と `at` を持つ。`words` は `0` を必ず持ち、鍵は `0`・`1`・`2` だけ。それぞれ文字列で、長さ 1 以上 20 以下、空白以外の文字を含む。`at` はサーバーの時刻。`choice` と `text` は持てない。
- `free` と、それ以外（アンケート）は今のまま。ただし、どちらも `words` を持てない。

規則を変えるので、先生に貼り直してもらう。新しいアプリを公開する前に貼る。

### 4.3 同じ言葉の決まり

- 送る言葉: 前後の空白を取る。空、または 20 文字（JavaScript の `length`）をこえるものは捨てる。
- 言葉の鍵（同じ言葉かどうかを決める値）: 送る言葉を、Unicode の NFKC で正し（全角・半角をそろえる）、つづく空白を 1 つにし、小文字にしたもの。
- 画面に出す形: 同じ鍵の言葉のうち、いちばん多く書かれた形。同じ数なら、先に届いた方。
- 人数: その鍵の言葉を書いた生徒の数。1 人が同じ鍵を 2 回書いても 1。
- `host/hidden` の鍵にするときは、データベースの鍵に使えない文字（`. $ # [ ] /` と制御文字）を避けるため、言葉の鍵を符号化する（`encodeURIComponent` のあと、`.` を `%2E` に）。

### 4.4 言葉を `pub` に書かない

自由記述と同じ。先生の端末が `inbox` から雲を作る。生徒の端末が知るのは `resultsVisible` だけ。

### 4.5 かくす・授業の終了・通信が切れたとき

自由記述の設計の 4.5〜4.7 と同じ。「かくす」は端末にも記録し（`classpulse:hidden:<sid>`）、読み直しても出さない。履歴には言葉と人数だけを残し、匿名 ID は残さない。生徒の送信は、端末に保管して自動で送り直す。保管する値の形は「言葉の配列」。

## 5. 確かめ方

- 自動テスト: 同じ言葉の決まり（全角・半角、大文字・小文字、空白、1 人の重複）、雲の一覧（人数、並び、かくす、60 語の上限）、履歴（匿名 ID が残らない）、生徒側の送信（書き直し、保管、締切）、先生側の状態（非表示の間は言葉が無い）、規則の文字列。
- 練習モードの通し確認: 作る → 発表 → 3 人分の言葉（タブ 2 つ＋書き直し）→ 件数だけ → 表示 → 大きさのちがい → かくす → 読み直し → 締切 → 終了 → 履歴。表示前の発表画面の HTML に言葉が無いこと、どの画面の HTML にも匿名 ID が無いこと。アンケート・自由記述がまざった教材で通ること。
- 本物の Firebase での確認は、先生にお願いする。

## 6. 実装する人に任せること

- 文字の大きさの決め方（最小と最大、人数からの計算）。教室の後ろから、いちばん小さい言葉も読めること。
- 言葉の色（`css/base.css` の色から、背景との明るさの差が足りるものを使う）。
- 並びの決め方、タップしたときの確認の見た目。
- モジュールと関数の分け方。自由記述の作りを、できるだけ共通にする。

## 7. 未確認の前提

- 30 人 × 3 語（最大 90 語）で、発表画面が読みやすいこと。
- 学校の iPad の日本語入力で、3 つの入力欄がふつうに使えること。
