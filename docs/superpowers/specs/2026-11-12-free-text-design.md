# 自由記述の設計書（段階 2 の 1 回目）

- 作成日: 2026-11-12
- もとになる設計書: `docs/superpowers/specs/2026-11-11-classpulse-design.md`（以下「全体設計」）
- 要件定義書の項目: 4.2 の自由記述、4.4 の匿名、4.5 の一部（非表示）

この文書で「ユーザーの決定」と書いたものは先生が決めたこと、「Claude の判断」と書いたものは Claude Code が決めたことである。

## 1. 目的

授業で「理由を書かせたあと、いくつか選んで紹介する」ができるようにする（ユーザーの決定）。

試作1 は選択式アンケートだけだった。ここに、文章で答える質問を 1 種類足す。試作1 の進行の規則（次へ進むと締切、締切は開け直さない、非公開の間は結果が画面に出ない）は、そのまま自由記述にも当てはめる。

## 2. 入れるもの・入れないもの

### 入れるもの

- スライドの種類「自由記述」。質問文だけを持つ。
- 生徒: 入力欄と「送信」。締切前なら書き直して送り直せる。1 人 1 件として数える。
- 先生（教室に映る画面）: 書いている間は件数だけ。「結果を表示」で文章の一覧。タップで 1 件を大きく表示。1 件ずつ「かくす」。
- 授業の結果の画面: 集まった文章をすべて読める。

### 入れないもの

- 映す前に 1 件ずつ承認する仕組み、不適切な言葉の自動検出（Claude の判断: 今回は入れない。先生は「選ぶときに全員の文章が教室の画面に映ってよい」と決めている）。
- 名前つきの回答（ユーザーの決定: だれが書いたかは知らなくてよい）。
- 生徒の端末に、ほかの生徒の文章を出すこと（Claude の判断）。
- ワードクラウド、クイズ、評価・投票、CSV などの出力。
- 文章の並べかえ、ピン留め、いいね。

### してはいけないこと

- 「結果を表示」を押す前に、先生の画面へ文章を 1 文字でも出す（件数だけを出す）。
- 文章に、生徒の名前や、端末の匿名 ID を付けて画面に出す・履歴に残す。
- ほかの生徒の文章を、生徒の端末へデータとして届ける（下の 4.3）。
- 締切済みの質問の受付を再開する。

## 3. 画面

言葉づかいと部品は、試作1 の画面にそろえる。色・余白・角丸・フォントは全体設計の 4 章と要件定義書 7 章のとおり。

### 3.1 スライド編集

- スライドを追加する所に「自由記述」を足す（今は「スライド」と「アンケート」）。
- 自由記述のスライドで編集できるのは、質問文だけ。選択肢や「結果の出し方」は無い。
- 質問文が空のままだと、アンケートと同じ扱いで、発表を始める前に知らせる。
- スライド一覧の縮小表示とキャンバスには、質問文と、入力欄の見本（押せない）を出す。

### 3.2 生徒の画面

- 質問文、入力欄（複数行）、残りの文字数、「送信」ボタン。
- 文字数は 200 文字まで（Claude の判断）。数え方は JavaScript の `length`（絵文字は 2 と数えることがある）。規則（4.2）と同じ数え方にするため。
- 前後の空白を取りのぞいた結果が空のときは、送信できない。
- 送ったあとは、アンケートと同じ送信状態の表示（送信中・送信済み・未送信で保管中・送信できませんでした・締切）を出す。
- 送信済みのあとも入力欄は編集でき、内容が送った文章と違うときは「送信」が「送り直す」になる。送り直すと前の文章を上書きする。
- 一時停止中と締切後は、入力欄を編集できない。送った文章があれば、そのまま読める。
- 書きかけの文章は、端末に一時保存する（ページを読み直しても消えない）。授業が終わったら消す。
- 先生が結果を表示している間、生徒の端末には文章の一覧を出さない。「みんなの回答は、前の画面を見てください」と出す。

### 3.3 先生の発表画面（教室に映る）

- 結果を表示する前: 質問文と「回答 12 件 / 参加 30 人」。文章は出さない。
- 「結果を表示」を押したあと: 文章を、読みやすい大きさのカードの一覧で出す。件数が多いときは縦にスクロールする。届いた順（4.4）。
- 表示中に新しい文章が届いたり、書き直されたりしたら、一覧に反映する（アンケートの集計と同じく 0.5 秒に 1 回まで）。
- カードをタップすると、その 1 件を画面いっぱいに大きく表示する。もう一度タップするか「一覧にもどる」で戻る。大きく表示しているのは 1 件だけ。
- 各カードに「かくす」ボタン。押すと確認を出し、「かくす」を選ぶと一覧から消える。授業中は元に戻せない（Claude の判断: 画面をシンプルに保つ。履歴では読める）。
- かくした文章の生徒が書き直して送り直した場合も、かくしたままにする（かくす対象は人で、文章ではない）。
- 「結果をかくす」を押すと、一覧も、大きく表示していた 1 件も消える。
- 一時停止・再開、前へ・次へ、授業の終了は、アンケートと同じ。
- だれが書いたかを示すものは、画面のどこにも出さない。

### 3.4 授業の結果（履歴）

- 質問ごとに、アンケートは今までどおり件数と割合。自由記述は、件数と、文章の一覧。
- 授業中にかくした文章は「授業中にかくした回答」と分けて出す。

## 4. データ

### 4.1 構造の変更

```
teachers/<uid>/decks/<教材ID>/slides/<スライドID>/
  type: "content" | "poll" | "free"
  free の場合: question

sessions/<授業ID>/
  pub/polls/<スライドID>/        … 自由記述のスライドにも作る（名前は polls のまま）
    status, resultsVisible        … 自由記述は最初 resultsVisible: false
  inbox/answers/<スライドID>/<生徒のuid>:
    アンケート: { choice, at }
    自由記述:   { text, at }
  host/hidden/<スライドID>/<生徒のuid>: true   … 先生がかくした回答。先生だけが読み書きできる

teachers/<uid>/history/<授業ID>/questions[]:
  アンケート: { slideId, type:"poll", question, options, counts, total }
  自由記述:   { slideId, type:"free", question, texts:[文...], hiddenTexts:[文...], total }
```

- `type` の無い古い履歴は、アンケートとして読む。
- `pub/polls` の名前は変えない（Claude の判断: 進行の規則がそのまま使え、試作1 のデータとも食いちがわない）。
- `total` は、かくしたものも含めた回答の件数。

### 4.2 規則（`docs/firebase/rules.json`）

`inbox/answers/<スライドID>/<uid>` の検証を、スライドの種類で分ける。書きこみの条件（本人、授業が `live`、その質問が `open`、今のスライドである）は変えない。

- 授業の写し（`sessions/<sid>/deck/slides/<スライドID>/type`）が `free` のとき: `text` と `at` を持つ。`text` は文字列で、長さ 1 以上 200 以下。`at` はサーバーの時刻。ほかの項目は持てない。
- それ以外のとき: 今までどおり（`choice` と `at`）。

`host` には規則を足さない。授業の持ち主の先生だけが `sessions/<sid>` を読み書きできる今の規則で足りる（生徒は読めない）。

規則を変えるので、先生に `rules.json` を貼り直してもらう必要がある。**新しいアプリを公開する前に貼り直す**（古い規則のままだと、自由記述の送信が拒否される。新しい規則は古いアプリでもそのまま動く）。

### 4.3 文章を `pub` に書かない

アンケートの集計は、生徒の端末に結果を出すために `pub/results` に書いている。自由記述の文章は、**`pub` に書かない。** 先生の端末は `inbox` を自分で読めるので、教室に映す一覧はそこから作れる。生徒の端末は文章を表示しないので、届ける必要がない。

- 生徒の端末が知るのは、`pub/polls/<スライドID>/resultsVisible`（結果を表示中かどうか）だけ。
- これで、ほかの生徒の文章も、端末の匿名 ID も、生徒の端末へは届かない。

### 4.4 並び順と数え方

- 1 人 1 件。`inbox/answers/<スライドID>/<uid>` に上書きするので、書き直しても件数は増えない。
- 一覧の並びは `at`（最後に送った時刻）の古い順。同じ時刻のときの順は、実装する人に任せるが、表示のたびに変わらないこと。
- かくした回答は一覧に出さないが、件数には数える。

### 4.5 授業の終了

- 履歴を作るとき、自由記述は文章だけを残す。端末の匿名 ID は残さない。かくしたものは `hiddenTexts` に分ける。
- 終了の後片づけで、`inbox` と一緒に `host` も消す。
- 終了の順番（先に全質問を締切 → `inbox` を読み直す → 履歴を保存 → 終了）は試作1 のまま。`host/hidden` も、このとき読み直したものを使う。

### 4.6 通信が切れたとき

- 生徒: アンケートと同じ。送れなかった文章は端末に保管し、つながったら自動で送る。そのとき締切済みなら、その旨を出す。
- 保管中に生徒が文章を書き直した場合は、最後の文章だけを送る。

### 4.7 点検で決めたこと（Claude の判断）

- 「かくす」は、押したらすぐ画面から消す。`host/hidden` への書きこみは裏で行い、失敗したら再試行する。再試行しても書けない間は、先生の画面に「かくした回答を保存できていません」と出す。書きこみが済んでいなくても、その端末の画面には二度と出さない。直後に「次へ」を押しても同じ。
- `host/hidden` は、発表画面を開いたときに 1 回読み、授業の終了のときにもう 1 回読む。購読はしない（接続を増やさない。先生は 1 つのタブで発表する前提）。再読み込みのあとも、かくした回答はかくれたままになる。
- 締切済みの自由記述のスライドに「前へ」で戻ったとき、結果を表示中なら一覧が出る。「かくす」も使える。受付は再開しない。
- 生徒の端末に送信済みの記録が無いとき（端末の保存が消えた、など）は、アンケートと同じ照合のしくみを使う。サーバーにある自分の文章が見つかれば、それを送信済みとして扱う。発表画面を開いたときに、自分の文章をわざわざ読み戻すことはしない。
- 端末に保管する回答の形は、`choice` を持つものと `text` を持つものの両方を扱えるようにする。古い形（`choice` だけ）で保管されているものは、そのまま読める。

## 5. 練習モード（`?demo=1`）

練習モードでも自由記述が同じように動くこと。練習モードは規則を調べないので、200 文字と空文字の制限は、画面の側でも必ず行う。

## 6. 確かめ方

- 自動テスト（`node --test "tests/*.test.js"`）: 教材の操作と検証、授業の組み立て（自由記述は `resultsVisible: false`）、履歴の組み立て（文章の分け方、ID が残らないこと、古い履歴の読み方）、生徒側の送信の状態（書き直し、保管、締切）、先生側の一覧の組み立て（並び、かくす、件数）。
- 練習モードの通し確認（先生のタブ 1 つ、生徒のタブ 2 つ）: 作る → 発表 → 書く → 件数だけが出る → 表示 → 一覧 → 大きく表示 → かくす → 書き直し → 次へで締切 → 終了 → 履歴。結果を表示する前の先生の画面の HTML に、文章が含まれないことを確かめる。
- 本物の Firebase での確認は、先生にお願いする（規則の貼り直し、送信、200 文字をこえる送信が拒否されること）。

## 7. 実装する人に任せること

- カードの大きさ、列の数、大きく表示するときの文字の大きさ（教室の後ろから読めること）。
- 書きかけの文章を端末に保存するときの鍵の名前と、保存するタイミング。
- 生徒側・先生側のモジュールの、関数の分け方と名前。
- 自由記述のスライドの、編集画面での見本の見た目。

## 8. 未確認の前提

- 30 人が同時に 200 文字を送っても、先生の iPad の一覧が重くならないこと。練習モードでは 2 人でしか確かめられない。
- 学校の iPad の日本語入力（変換の途中）で、文字数の表示や送信がおかしくならないこと。先生に iPad で確かめてもらう。
