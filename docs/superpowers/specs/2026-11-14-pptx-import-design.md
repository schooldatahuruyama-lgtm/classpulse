# PowerPoint（.pptx）の直接取りこみの設計書

- 作成日: 2026-11-14
- もとになる設計書: `2026-11-11-classpulse-design.md`（段階 4「PowerPoint・Google スライドの取込み」）、`2026-11-12-pdf-import-design.md`
- 要件定義書の項目: 4.1（37 行）、301 行（変換の精度、取込みできない要素の説明）

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。

## 1. 目的と前提

- **ユーザーの決定:** PowerPoint のファイルを直接取りこめるようにする（配置やフォントがくずれやすいこと、PDF にすれば見た目どおりに取りこめることは、先生に伝えてある）。
- 「PDF から作る」は、1 ページが 1 枚の画像になり、文字を直せない。「PowerPoint から作る」は、**文字と画像を、あとから直せる要素として**取りこむ。見た目は元と同じにならない。これが 2 つのちがい（Claude の判断）。
- Google スライドは直接は読めない（Google の審査が要る権限か、外部のスクリプトが要るため）。Google スライドは「ファイル → ダウンロード → Microsoft PowerPoint (.pptx)」で保存したものを、この機能で取りこめる。

## 2. 入れるもの・入れないもの

### 入れるもの

- ホームに「PowerPoint から作る」。`.pptx` を 1 つ選ぶと、新しい教材ができる。
- スライド 1 枚が、資料スライド 1 枚になる。取りこむのは、
  - 文字の入った箱（題、本文、テキストボックス、文字の入った図形の文字）→ 文字の要素
  - 画像（PNG・JPEG・GIF・BMP・WebP）→ 画像の要素
  - グループの中の文字と画像（位置を計算して取りこむ）
- 取りこめなかったものの数を、終わったときに知らせる。

### 入れないもの（取りこまず、数だけ知らせる）

- 図形そのもの（四角・矢印などの形と塗り）、線、表、グラフ、SmartArt、数式、動画・音声、手書き、EMF・WMF・SVG・TIFF の画像。
- 背景（色・画像）、テーマの色・フォント、アニメーション、画面の切りかえ、ノート、コメント。
- 文字の一部だけの書式（1 つの箱の中で、色や太さが途中で変わるもの。箱のはじめの書式を使う）。箇条書きの段の深さ、行間、縦書き、回転、画像の切りぬき。
- 非表示のスライド（取りこまず、数を知らせる）。
- 古い形式（`.ppt`）、Keynote、パスワードの付いたファイル。

### してはいけないこと

- ファイルや中身を、端末の外へ送る。
- 外部のスクリプト・ライブラリを足す（ZIP の展開はブラウザの `DecompressionStream('deflate-raw')`、XML の読み取りは自分で書いた小さな読み取り器で行う）。
- ファイルの中の XML・文字列を、HTML として画面に入れる（文字は、今の文字の要素と同じく `textContent` で出る）。
- ファイルの中の外部への参照（リンク、外にある画像）を読みに行く。
- 取りこみを途中でやめた・失敗したときに、教材を作る。

## 3. 読み取りのしくみ（新しい純粋なモジュール。Node でテストできる）

### 3.1 ZIP（`js/zip-read.js`）

- ファイルの末尾から中央ディレクトリを読み、名前 → 項目の表を作る。圧縮の方式は 0（無圧縮）と 8（deflate）だけ。暗号化の印がある・ZIP64・複数に分かれた ZIP は「読めない」にする。
- 中身は、必要な項目だけを、必要になったときに展開する。
- 上限（`CONFIG.pptx`）: 項目の数 5000、XML 1 つの展開後 5MB、画像 1 つの展開後 30MB、展開した合計 200MB。こえたら「読めない」（展開しながら数え、こえた時点で止める）。
- 項目の名前は表の鍵としてだけ使う（ファイルの場所として使わない）。

### 3.2 XML（`js/xml-read.js`）

- 要素・属性・文字・CDATA・コメント・処理命令を読める最小の読み取り器。返す形は `{ name, attrs, children, text }` の木。
- `<!DOCTYPE` があれば失敗にする（実体の展開をしない）。実体は `&amp; &lt; &gt; &quot; &apos;` と数値の形だけ。
- 名前は接頭辞つきの文字列のまま（`p:sp`、`a:t`）で比べる（PowerPoint と Google スライドが出す形で足りる）。
- 入れ子の深さ 200 まで。

### 3.3 スライドの読み取り（`js/pptx-import-logic.js`）

- 順番: `ppt/presentation.xml` の `p:sldIdLst` と `ppt/_rels/presentation.xml.rels`。大きさは `p:sldSz`（無ければ 9144000 × 6858000）。
- 参照先の名前は、`ppt/` の中に正す（`..` を解き、`ppt/` の外・外部（`TargetMode="External"`）は使わない）。
- 非表示（`p:sld` の `show="0"`）は飛ばして数える。
- `p:spTree` の子を、上から順に（重なりの順のまま）見る。
  - `p:sp`: `p:txBody` の文字が空白だけでなければ、文字の要素。文字が無ければ「図形」として数える。
  - `p:pic`: `a:blip` の `r:embed` → スライドの rels → 画像の項目。使える形式なら画像の要素、使えなければ「画像」として数える。
  - `p:grpSp`: グループの `a:xfrm`（`a:off`・`a:ext`・`a:chOff`・`a:chExt`）で、中の位置を計算して、中身を同じように見る（入れ子も）。
  - `p:graphicFrame`（表・グラフ・SmartArt）、`p:cxnSp`（線）、そのほか: 種類ごとに数える（「表・グラフ」「線」「そのほか」）。
- 位置と大きさ: `p:spPr/a:xfrm`。無いとき（レイアウトから受けつぐプレースホルダー）は、スライドのレイアウト → マスターの順に、同じ `p:ph` の `type`（無ければ `idx`）の箱の `a:xfrm` を使う。それも無ければ、題（`title`・`ctrTitle`）は上の帯（x 5%、y 5%、幅 90%、高さ 18%）、それ以外は下の広い所（x 5%、y 25%、幅 90%、高さ 65%）。
- スライドが 16:9 でないときは、今の `fitToSlide` と同じ考え方で、縦横比を保って中央に置いた範囲の中に、要素を置く。最後に `clampItem` で枠の中に収める。
- 文字:
  - 段落（`a:p`）ごとに 1 行。`a:r/a:t` をつなぎ、`a:br` は改行、`a:fld` は中の `a:t`。箇条書きの印は付けない。末尾の空の行は取る。1 つの箱は 2000 文字まで（こえた分は切り、「そのほか」に数える）。
  - 大きさ: 箱の中のはじめの `a:rPr` の `sz`（1/100 ポイント）を、スライドの幅に対する % にして（`sz / 100 × 12700 ÷ スライドの幅(EMU) × 100`）、`s` 2.5・`m` 4・`l` 6・`xl` 9 のいちばん近いもの。`sz` が無ければ、題は `l`、それ以外は `m`。
  - 太字: はじめの `a:rPr` の `b="1"`。題は太字。
  - そろえ: はじめの `a:pPr` の `algn`（`ctr` → 中央、`r` → 右、ほかは左）。中央の題（`ctrTitle`）は中央。
  - 色: はじめの `a:rPr` の `a:solidFill/a:srgbClr` があれば、文字に使える色（`TEXT_COLORS`）のいちばん近いもの。白に近い色（背景を取りこまないので読めなくなる）と、色の指定が無いものは、ネイビー（`#1F2A6B`）。
  - 高さの直し: 選んだ大きさで文字が箱に入りきらないと切れて見えるので、行の数を見つもって（1 行に入る文字数 ＝ 箱の幅 ÷ 文字の大きさ。全角を 1、半角を 0.5 と数える）、足りなければ高さを広げる（スライドの下まで）。
- 画像: 同じ画像が何度も使われていても、要素ごとに別の画像として持つかどうかは、今の編集の画面が画像を消すときの動き（ほかの要素が同じ画像を使っているかを見るか）に合わせて、安全な方を選ぶ。

### 3.4 画像の変換と、教材の組み立て（ブラウザの部品を使う `js/pptx-import.js`）

- 画像は、今の `compressImage`（JPEG にして縮める。透明は白）で変える。1 つの上限は、`min(CONFIG.image.maxBytes, floor(CONFIG.image.deckMaxBytes ÷ 取りこむ画像の数))`。
- 変えられなかった画像（こわれている、など）は「画像」として数えて飛ばす（全体は止めない）。
- 上限: ファイル 50MB、スライド 100 枚（非表示をのぞいて数える）。
- 取りこめる要素が 1 つも無いスライドは、空の資料スライドとして残す（枚数と順番を元と合わせる）。
- 教材の名前は、ファイル名から（今の PDF と同じ決まり。既定は「PowerPoint の教材」）。
- 進みぐあい「PowerPoint を読みこんでいます… 3 / 12 枚」と「やめる」（今の PDF と同じ形）。

## 4. 画面

- ホームの「PDF から作る」のとなりに「PowerPoint から作る」。ファイルを選ぶ画面は `.pptx` だけ。
- 終わったあとの動きは、今の PDF の取りこみと同じにする。そのうえで、まとめを先生が読める形で出す:
  - 「12 枚のスライドを取りこみました。文字と画像だけを取りこんでいます。配置や文字の大きさは、元と同じにはなりません。見た目をそのまま使いたいときは、PowerPoint で PDF に書き出して「PDF から作る」を使ってください。」
  - 取りこめなかったものがあれば: 「取りこめなかったもの: 図形 5、表・グラフ 2、線 3、画像 1、そのほか 1、非表示のスライド 1」（0 のものは出さない）。
- 失敗の文:
  - `.pptx` でない →「PowerPoint（.pptx）のファイルを選んでください。古い形式（.ppt）は、PowerPoint で .pptx に保存し直してください。」
  - 大きすぎる →「ファイルが大きすぎます（50MB まで）。」
  - 枚数が多い →「このファイルは N 枚あります。取りこめるのは 100 枚までです。」
  - ブラウザに展開の部品が無い →「このブラウザでは PowerPoint を取りこめません。ブラウザを新しくするか、PDF に書き出して「PDF から作る」を使ってください。」
  - 読めない（こわれている・パスワード・上限をこえた）→「この PowerPoint を読みこめませんでした。パスワードが付いていないか、ファイルがこわれていないか確かめてください。」
  - やめた →「PowerPoint の取りこみをやめました。教材は作っていません。」
  - 画像を入れると教材の上限（5MB）に収まらないなど、保存できない → 今の PDF と同じ文。

## 5. 知っている限界

- 見た目は元と同じにならない（背景・図形・表・グラフが無い、文字の大きさは 4 段階、色は 6 色、フォントはアプリのもの）。
- テーマやレイアウトで決まっている文字の大きさ・色は読まない（箱に書いてあるものだけ）。
- 文字が重なる・はみ出すことがある。取りこんだあと、編集の画面で直す前提。
- 画像は JPEG になる（透明は白）。枚数が多いと、1 枚ずつが小さく（あらく）なる。
- iPad の古い Safari（16.3 以前）では使えない。

## 6. 確かめ方

- 自動テスト（テストの中で小さな .pptx を組み立てる）: ZIP（無圧縮・deflate、こわれた末尾、暗号化の印、上限）、XML（実体、DOCTYPE をことわる、深さ）、順番、非表示、位置（箱・レイアウトから受けつぐ・既定・グループ・4:3）、文字（改行、大きさ・太字・そろえ・色、白い文字、2000 文字、高さの直し）、画像の参照（`ppt/` の外・外部をことわる、使えない形式）、数え方、まとめの文、失敗の文、途中でやめたら教材を作らない。
- ブラウザ（練習モード）: 手元で作った .pptx を取りこみ、文字と画像が編集できること、まとめの文、やめる、こわれたファイル。
- 本物の授業の資料・iPad では、先生が試す。規則の貼り直しは、いらない。
