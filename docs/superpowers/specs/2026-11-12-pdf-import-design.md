## 1. 目的

先生がすでに持っている資料（PDF）から、教材を作れるようにする（ユーザーの決定）。PowerPoint や Google スライドで作った資料も、PDF に書き出せば取り込める。

授業で使う PDF は 30 ページ以下（ユーザーの決定）。

## 2. 入れるもの・入れないもの

### 入れるもの

- 教材の一覧に「PDF から作る」を足す。PDF を選ぶと、新しい教材ができる。
- PDF の 1 ページが 1 枚のスライドになる。ページの見た目を画像として取り込む。
- 取り込んだあとは、ふつうの教材と同じ。スライドの間にアンケートや自由記述を足せる。順番を変えられる。いらないページを消せる。文字や画像を上に足せる。

### 入れないもの

- 取り込んだページの文字を打ち直すこと（画像なので、できない）。
- 今ある教材の途中に PDF を足すこと（Claude の判断: まず新しい教材として作る形だけにする。必要になったら足す）。
- ページを選んで取り込むこと（全ページを取り込み、いらないページはあとで消す）。
- PowerPoint・Google スライドのファイルを直接読むこと。動画・音声・アニメーション。
- 31 ページ以上の PDF、パスワード付きの PDF。

### してはいけないこと

- PDF のファイルそのものを、端末の外へ送る。読み取りと画像への変換は、すべて先生の端末の中で行う。データベースに入るのは、変換した画像だけ。
- 取込みの途中で失敗したとき、ページの欠けた教材を黙って残す。
- 無料の範囲（Spark プラン）をこえる設定にする。

## 3. 画面

### 3.1 教材の一覧

- 「新しい教材」の隣に「PDF から作る」。押すと、ファイルを選ぶ画面が出る（PDF だけを選べる）。
- 選ぶと、進みぐあいを出す: 「PDF を読みこんでいます… 3 / 24 ページ」と「やめる」ボタン。
- 終わると、その教材の編集画面を開く。教材の名前は、PDF のファイル名（`.pdf` を取ったもの）。
- 「やめる」を押したとき、失敗したとき: 教材は作らない。一覧に戻り、何が起きたかを文で出す。

### 3.2 知らせる文（例。言い回しは実装する人が試作1 にそろえてよい）

| 起きたこと | 出す文 |
|---|---|
| 31 ページ以上 | 「この PDF は 42 ページあります。取り込めるのは 30 ページまでです。ページを減らした PDF で、もう一度ためしてください。」 |
| パスワード付き | 「パスワードの付いた PDF は取り込めません。」 |
| 読めないファイル | 「この PDF を読みこめませんでした。ファイルがこわれていないか確かめてください。」 |
| ファイルが大きすぎる（50MB をこえる） | 「ファイルが大きすぎます（50MB まで）。」 |
| 保存に失敗 | 試作1 の保存失敗と同じ扱い（再試行できる） |

## 4. 作り方

### 4.1 PDF を読む部品

- Mozilla の pdf.js（`pdfjs-dist`、Apache-2.0）を使う。ビルドの仕組みは足さず、配布されているファイルをそのまま `js/lib/pdfjs/` に置く（QR コードの部品と同じやり方。ライセンスの文も一緒に置く）。
- 版は 1 つに決めて、その番号を `js/lib/pdfjs/` の中に書き残す。古めの iPad の Safari でも動くように、配布物の中の「legacy」のビルドを使う。
- pdf.js は大きい（1MB をこえる）ので、「PDF から作る」を押したときに初めて読みこむ。生徒の画面や、ふだんの先生の画面では読みこまない。
- 公開用のブランチを作る `tools/pages-branch.ps1` は `js` フォルダを丸ごと入れるので、変更はいらないはずである。実装する人が確かめる。

### 4.2 ページを画像にする

- 1 ページずつ順に画像にする（まとめて行わない。iPad のメモリを使いすぎないため）。
- 画像は JPEG。長辺は `CONFIG.image.maxEdge`（1280）まで。
- 1 枚の大きさの上限は、「`CONFIG.image.maxBytes`（200KB）」と「教材の上限 5MB ÷ ページ数」の小さい方。30 ページなら 1 枚およそ 170KB。これで、30 ページでも必ず教材の上限に収まる。
- 上限に収まるまで、今の画像の圧縮（`js/image.js`）と同じ考え方で、画質を下げ、それでもだめなら大きさを下げる。圧縮の部分は、今あるものと共通にする。
- 透明な部分は白にする。

### 4.3 スライドにする

- 1 ページ = `content` のスライド 1 枚。その中に画像の要素を 1 つ置く。
- 画像は、縦横比を変えずに、スライドに収まる最大の大きさで、中央に置く（縦長のページなら左右に余白ができる）。
- データの形は試作1 のまま（`content` スライドと画像の要素）。**データベースの構造も規則も変えない。**
- 教材は、全ページの変換が終わってから、1 回で保存する。途中まで保存しない。

### 4.4 データの量についての注意

- 発表を始めると、教材の写しを生徒の端末がそれぞれ受け取る。5MB の教材を 30 人が受け取ると、1 回の授業で約 150MB。
- Firebase の無料の範囲は、受け取りが 1 か月 10GB まで。上限いっぱいの PDF 教材なら、1 か月におよそ 60 回の授業が目安になる。
- この目安を README に書く。こえそうな使い方になったら、段階 5 で画像の置き場所を考え直す。

## 5. 練習モード（`?demo=1`）

練習モードでも同じように取り込めること。練習モードは教材を端末の `localStorage` に入れており、容量が小さい（多くのブラウザで 5MB 前後）。入りきらないときに、黙って失敗せず、保存できなかったことが分かること。確認には、ページ数の少ない PDF を使う。

## 6. 確かめ方

- 自動テスト: 1 枚の上限の計算、スライドへの収め方（横長・縦長・正方形）、ページ数とファイルの大きさの判定、教材の組み立て（ページ順、スライドと画像の対応、合計が上限以下）。pdf.js と canvas を使う部分は自動テストにしない。
- ブラウザでの確認: 横長（スライドを書き出したもの）と縦長（A4 の文書）の PDF、日本語の文字が入った PDF、31 ページの PDF、PDF ではないファイル、途中で「やめる」。取り込んだ教材にアンケートを足し、発表して、生徒のタブでページが見えること。
- 確認用の PDF は、手元で作る（外から持ってこない）。
- 先生にお願いする確認: 学校の iPad で、ふだん使っている PDF を取り込めること。

## 7. 実装する人に任せること

- pdf.js のどの版を使うか（legacy のビルドがあり、今の Safari と Chrome で動く版）。
- 進みぐあいの表示の見た目。
- モジュールの分け方と名前。
- 取り込んだページの文字がぼやけるとき、上限の中での画質と大きさの配分。

## 8. 未確認の前提

- 学校の iPad の Safari で、pdf.js の legacy のビルドが動くこと。動かない場合は、古い版に下げる。
- 30 ページの PDF を iPad で取り込むのにかかる時間。長すぎるようなら、進みぐあいの表示を見直す。
- 写真の多い PDF で、1 枚 170KB の画像が授業で読める画質になること。
