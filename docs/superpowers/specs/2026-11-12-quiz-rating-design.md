# クイズと 5 段階評価の設計書（段階 2 の 4 回目）

- 作成日: 2026-11-12
- もとになる設計書: `2026-11-11-classpulse-design.md`（全体設計）
- 要件定義書の項目: 4.2 のクイズ、評価・投票

「ユーザーの決定」は先生が決めたこと、「Claude の判断」は Claude Code が決めたことである。先生が決めたのは「クイズと評価・投票を先に作る」ことで、下の中身はすべて Claude の判断である（チャットで説明済み）。

## 1. 目的

- クイズ: 正解のある選択問題。正解と正答率を、先生が出したいときに出す。
- 5 段階評価: 1〜5 から 1 つ選ぶ。それぞれの人数と平均を出す。
- 「投票」は、今のアンケート（`poll`）でできるので、新しく作らない。

どちらも、今のアンケートのしくみ（回答 `{ choice, at }`、集計 `{ counts, total }`、`pub/polls` の進行）にそのまま乗せる。**Firebase の規則は変えない。**

## 2. 入れるもの・入れないもの

### 入れるもの

- スライドの種類「クイズ」（`quiz`）: 質問、選択肢 2〜6 個、正解 1 つ。
- スライドの種類「5 段階評価」（`rating`）: 質問、両はしの言葉（1 の側・5 の側。空でもよい）、結果の出し方（アンケートと同じ 2 つ）。
- 授業履歴に、クイズ（選択肢ごとの人数、正解、正答率）と評価（1〜5 の人数、平均）。

### 入れないもの

- 正解が 2 つ以上あるクイズ、記述式のクイズ、点数の合計、順位、制限時間。
- 5 段階以外の評価（星の数を変える、10 段階など）。
- だれが正解したかの記録（匿名のまま）。

### してはいけないこと

- 「正解を表示」の前に、正解を生徒の端末へ届ける（授業の写し `sessions/<sid>/deck` にも `pub` にも入れない）。
- 「正解を表示」の前に、教室の画面へ正解や選択肢ごとの人数を出す。
- 正解を表示したあとに、回答を受け付ける（正解を見てから答えを変えられてしまう）。
- 締切済みの質問の受付を再開する。

## 3. 画面

### 3.1 スライド編集

- スライドを追加する所に「クイズ」と「5 段階評価」を足す。
- クイズ: アンケートと同じ編集（質問、選択肢の追加・削除）に、「正解」を選ぶ所を足す。作った直後は、1 つ目が正解。正解の選択肢を消したら、1 つ目を正解にする。正解より前の選択肢を消したら、正解がずれないようにする。「結果の出し方」は出さない。
- 評価: 質問、「1 の側の言葉」「5 の側の言葉」（それぞれ 20 文字まで、空でもよい）、「結果の出し方」。
- 質問文が空・選択肢が空のときの知らせは、アンケートと同じ。

### 3.2 生徒の画面

- クイズ: アンケートと同じ見た目で選んで送る。締切前なら変えられる。正解が表示されたら、正解の選択肢に「正解」の印、自分の答えについて「正解です」または「ざんねん。正解は『〇〇』です」、答えていなければ「正解は『〇〇』です」。選択肢ごとの人数も、アンケートの結果と同じ形で出す。色だけに頼らず、文字と印でも分かるようにする。
- 評価: 1〜5 のボタンが横に並ぶ。両はしに言葉。選んで送る。締切前なら変えられる。結果が表示されたら、1〜5 の人数と平均を出す。

### 3.3 先生の発表画面（教室に映る）

- クイズ:
  - 表示する前: 質問と選択肢、「回答 n 人 / 参加 m 人」。人数の内訳も正解も出さない。
  - ボタンは「正解を表示」。押すと、その質問を締め切り（`closed`）、選択肢ごとの人数、正解の印、「正答率 62%（8 / 13 人）」を出す。回答が 0 人のときは「正答率 —」。
  - 「正解をかくす」で、内訳と正解が消える（締切のまま。受付は再開しない）。もう一度「正解を表示」で出せる。
  - 一時停止・再開は、締切前だけ。
- 評価: アンケートと同じ動き。結果は、1〜5 の棒と「平均 3.8（13 人）」。平均は小数 1 けた。0 人のときは「平均 —」。

### 3.4 授業の結果（履歴）

- クイズ: 選択肢ごとの人数と割合、正解の印、正答率。
- 評価: 1〜5 の人数と割合、平均、両はしの言葉。

## 4. データ

### 4.1 教材

```
slides/<スライドID>/
  quiz:   type:"quiz", question, options:[文...（2〜6）], correct: 番号（0 から）
  rating: type:"rating", question, lowLabel, highLabel, resultMode:"live"|"manual"
```

### 4.2 授業（発表を始めたときの写し）

```
sessions/<授業ID>/
  deck/slides/<スライドID>/
    quiz:   type:"quiz", question, options            … correct は入れない
    rating: type:"rating", question, lowLabel, highLabel, options:["1","2","3","4","5"]
  host/quiz/<スライドID>: 正解の番号                   … 先生だけが読める（今の規則のまま）
  pub/polls/<スライドID>/ status, resultsVisible       … quiz は最初 false。rating は resultMode による
  pub/results/<スライドID>:
    poll・rating: { counts, total }
    quiz:         { counts, total, correct }           … 表示中だけ
  inbox/answers/<スライドID>/<uid>: { choice, at }     … アンケートと同じ
```

- 評価の写しに `options` を入れるのは、今の規則（「`choice` の番号の選択肢が授業の写しにあること」）をそのまま使うため。回答の `choice` は 0〜4（画面の 1〜5 から 1 を引いたもの）。
- 規則は、`free` と `cloud` 以外の種類をアンケートと同じに扱うので、`quiz` と `rating` はそのまま通る。**規則は変えない。**
- 正解は `host/quiz` に置く。`sessions/<sid>` の下で、持ち主の先生だけが読み書きできる場所（`host/hidden` と同じ）。

### 4.3 進行の決まり

- クイズで「正解を表示」: 1 回の書きこみで、`status` を `closed` に、`resultsVisible` を `true` にする。そのあと、集計と正解を `pub/results/<スライドID>` に書く（順番は、アンケートで結果を表示するときと同じしくみに乗せる）。
- 締め切ったあと・表示したあとに、通信の遅れで届いていた回答があっても、規則が拒否する（今のしくみ）。
- 「正解をかくす」: `resultsVisible` を `false` に、`pub/results/<スライドID>` を消す。
- 評価: アンケートと同じ。

### 4.4 履歴

```
quiz:   { slideId, type:"quiz", question, options, counts, total, correct, correctCount }
rating: { slideId, type:"rating", question, lowLabel, highLabel, counts（5 個）, total, average（小数 1 けた。0 人なら null） }
```

- 授業の終了のとき、`host/quiz` を読み直して使う。後片づけで `host` ごと消える（今のしくみ）。

## 5. 確かめ方

- 自動テスト: 教材の操作（正解のずれ、検証）、授業の組み立て（写しに `correct` が無い、評価に `options` がある、`host.quiz`）、進行（正解の表示で締切）、集計と履歴（正答率、平均）、生徒側（クイズ・評価で送れる、正解の表示のあとは送れない）、先生側の状態（表示前は内訳も正解も無い）。
- 練習モードの通し確認: クイズと評価を作る → 発表 → 2 人が答える → 表示前の発表画面と、生徒のタブが受け取っているデータ（`pub` と `deck`）に正解が無い → 「正解を表示」→ 締切・正解・正答率、生徒の画面に ○× → かくす → 評価の結果と平均 → 終了 → 履歴。アンケート・自由記述・ワードクラウドとまざった教材で通ること。
- 本物の Firebase での確認は、先生にお願いする（規則は変えていないので、貼り直しはいらない）。

## 6. 実装する人に任せること

- 評価のボタンと結果の見た目。正解・不正解の印と文の見た目（色だけに頼らない）。
- 関数の分け方。アンケートの作りを、できるだけ共通にして使う。

## 7. 未確認の前提
