# 教材のゴミ箱と復元 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 教材の「削除」をゴミ箱への移動に変え、30 日以内なら元に戻せるようにする。

**Architecture:** 一覧の項目（`deckIndex/<id>`）に `deletedAt` の印を付けるだけで、教材の中身は動かさない。読み書きは `js/repo.js`、日数の計算は純粋な関数（`js/trash.js`）、画面は新しい `js/views/trash.js`。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、`node --test "tests/*.test.js"`。

**Spec:** `docs/superpowers/specs/2026-11-13-trash-design.md`

**実行のしかた:** 小さい変更なので、指揮役がこのセッションで実装する（Ruling: 3 つのタスクが同じ関数を共有し、全部で数ファイル。別の実装役に分ける利点が小さい）。査読は `tools/codex-review.ps1`。

## Global Constraints

- `docs/firebase/rules.json`、`js/session-*.js`、`js/net.js` を変えない。
- ゴミ箱に移す・戻すときに、`decks/<id>` を読み書きしない。
- 画面の文は設計書 4 章のとおり。`innerHTML` を使わない。
- 今あるテスト（580 件）を壊さない（`saveDeck` の書き方を変えるので、書くパスを見ているテストは直す）。

## Review Focus

1. 別のタブの保存で、ゴミ箱の印が消えない。
2. `deletedAt` が数でない・未来の時刻の項目が、自動で消えない・画面をこわさない。
3. 元に戻した教材を、同じタブですぐ編集・保存できる（「削除済み」の印が残らない）。
4. ゴミ箱の教材を、編集の URL から開けない・発表できない。
5. 空にする・自動削除が、ゴミ箱に無い教材を消さない。
