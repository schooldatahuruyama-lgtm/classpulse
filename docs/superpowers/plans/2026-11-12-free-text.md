# 自由記述 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 文章で答える質問（スライドの種類 `free`）を足し、先生が教室の画面で一覧から選んで紹介できるようにする。

**Architecture:** 試作1 の進行のしくみ（`pub/polls` の `status` と `resultsVisible`）を自由記述にもそのまま使う。回答は `inbox/answers/<slideId>/<uid>: { text, at }`。文章は `pub` に書かず、先生の端末が `inbox` から一覧を作る。かくした回答は `sessions/<sid>/host/hidden/<slideId>/<uid>: true`。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、Firebase Realtime Database と Authentication（REST と EventSource）、`node --test "tests/*.test.js"`。パッケージは足さない。

**Spec:** `docs/superpowers/specs/2026-11-12-free-text-design.md`（もとの設計: `docs/superpowers/specs/2026-11-11-classpulse-design.md`）

## Global Constraints

- 作業の決まりは `CLAUDE.md` と `AGENTS.md` に従う。コミットは Claude Code（指揮役）が行う。実装する人は commit しない。
- 文字数の上限は 200（`CONFIG.free.maxLength = 200` を `js/config.js` に足す）。数え方は JavaScript の `length`。前後の空白を取りのぞいた結果が空なら送れない。
- スライドの種類の名前は `'free'`。回答の項目名は `text`。`pub/polls` の名前は変えない。
- 「結果を表示」の前に、先生の画面の DOM に文章を 1 文字も入れない（かくすのではなく、作らない）。
- 生徒の uid を、DOM（属性も含む）・`pub`・履歴に入れない。画面の操作と uid の対応は、JavaScript の中（クロージャや Map）だけで持つ。
- 文章を `pub` に書かない。自由記述では `pub/results/<slideId>` を書かない。
- 締切済みの質問を `open` に戻さない。次へ進むと締切。
- 画面の文は、ひらがな多めの試作1 の言い回しにそろえる。色・余白・フォントは `css/base.css` の変数を使う。
- 既存のテスト（339 件）を壊さない。DOM のテスト用ライブラリは足さない（画面はブラウザで確かめる）。
- 試作1 のデータ（`type` の無い履歴、`choice` だけの保管中の回答）が、そのまま読めること。

## Review Focus

1. 結果を表示する前の先生の画面に、文章が出ない・DOM に無い（教室に映っている）。
2. かくした回答が、書き直し・再読み込み・「前へ」で戻ったあとに、また映らない。
3. 生徒が送信中に書き直したとき、古い文章で新しい文章を上書きしない。最後の文章が残る。
4. 201 文字以上・空白だけ・文字列でない `text` が、画面でも規則でも通らない。
5. 試作1 のアンケートの動きが変わらない（同じ授業にアンケートと自由記述がまざっても）。

### Task 2: 生徒側の送信（outbox と session-client）

**Files:**
- Modify: `js/outbox.js`, `js/session-client.js`
- Test: `tests/outbox.test.js`, `tests/session-client.test.js`

**Interfaces:**
- Consumes: `normalizeText`, `CONFIG.free.maxLength`
- Produces:
  - outbox の 1 件は「値」を 1 つ持つ。値は、整数（`choice`）か、空でない文字列（`text`）。保管の形は `{ choice, state }` か `{ text, state }`。古い `{ choice, state }` はそのまま読める。整数でも文字列でもないものは読み捨てる
  - outbox の `send` が返す「サーバーに残っていた回答」は `{ choice }` か `{ text }`。`settle` も両方を受ける
  - session-client の状態（`onChange` に渡すもの）に、今のスライドが `free` のとき `kind:'free'`、送信済み・送信中の文章 `text`（無ければ `null`）が分かる項目を足す。アンケートのときの項目は変えない
  - `client.submitText(raw)`: 今のスライドが `free` で受付中のときだけ、`normalizeText(raw)` を通った文章を送る。通らなければ何もしない。送信済みと同じ文章なら送らない
  - `client.retry()` は、自由記述でも「最後に送ろうとした文章」を送り直す
  - 送信は `net.set(answerPath, { text, at: net.serverTimestamp() })`
  - 書きかけの文章の保存（`draft(slideId)` / `setDraft(slideId, raw)`）。鍵は `classpulse:draft:<sid>:<uid>`。授業が終わったら消す

### Task 3: 先生側の進行（session-host）

**Files:**
- Modify: `js/session-host.js`
- Test: `tests/session-host.test.js`

**Interfaces:**
- Consumes: `freeList`, `buildHistory(…, hidden)`
- Produces:
  - `host.start()` は、`sessions/<sid>/host/hidden` を 1 回読む（無ければ空）
  - host の状態に、今のスライドが `free` のとき: `kind:'free'`、`answerCount`（`freeList().total`）、`freeItems`。`freeItems` は、そのスライドの `resultsVisible` が `true` のときだけ `[{ uid, text }]`、それ以外は `null`（文章を状態に入れない）
  - `host.hide(slideId, uid)` → Promise。すぐに手元の `hidden` に入れて `onChange` を呼ぶ。`net.set('sessions/<sid>/host/hidden/<slideId>/<uid>', true)` を行い、失敗したら `CONFIG.reconnectDelayMs` ごとに再試行する。書けていないものがある間は、状態の `hiddenUnsaved` が `true`
  - 自由記述では `pub/results/<slideId>` を書かない（表示中も、切りかえのときも）。`setResultsVisible` は `resultsVisible` だけを書く
  - `host.end()`: 今までの順番のまま。`inbox` を読み直すとき `host/hidden` も読み直し、手元でかくしたもの（まだ書けていないものも）と合わせて `buildHistory` に渡す。後片づけで `host` も消す
  - `host.stop()` は、再試行のタイマーも止める
