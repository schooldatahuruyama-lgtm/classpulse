# Firebase の準備の手順書

ClassPulse は、授業中のデータのやりとりに Google の Firebase を使います。このページは、先生が自分で行う準備の手順です。順番にやれば大丈夫です。わからなくなったら、そこで止めて Claude Code に画面の様子を伝えてください。

**料金について:** プランは無料の「Spark プラン」のままにします。「Blaze プラン」への切り替えや、クレジットカードの登録、請求先の設定はしません。画面に「アップグレード」と出ても押さないでください。

必要なもの: Google アカウント（学校のものでも個人のものでも可）と、パソコンのブラウザ。

---

## 1. プロジェクトを作る

1. ブラウザで https://console.firebase.google.com/ を開き、Google アカウントでログインします。
2. 「プロジェクトを作成」（または「プロジェクトを追加」）を押します。
3. プロジェクト名に `classpulse` など好きな名前を入れて「続行」を押します。
4. 「Google アナリティクス」の画面が出たら、スイッチを**オフ**にして「プロジェクトを作成」を押します（アナリティクスは使いません）。
5. 「新しいプロジェクトの準備ができました」と出たら「続行」を押します。

## 2. Realtime Database を作る

1. 左のメニューの「構築」（または「Build」）を開き、「Realtime Database」を選びます。
2. 「データベースを作成」を押します。
3. 場所を聞かれたら、そのまま（または「シンガポール」など日本に近い場所）を選んで「次へ」を押します。
4. セキュリティルールは「**ロックモードで開始**」を選んで「有効にする」を押します。
5. データベースの画面の上に、`https://〜.firebasedatabase.app`（または `https://〜.firebaseio.com`）で始まる URL が出ます。これを**控えておきます**（あとで Claude Code に伝えます）。最後に `/` は付けません。

## 3. ルールを貼って公開する

1. Realtime Database の画面で「ルール」のタブを開きます。
2. 今ある文字をすべて消します。
3. このフォルダの `docs/firebase/rules.json` を開き、中身を**すべてコピー**して、ルールの欄に貼ります。
4. 「公開」を押します。

## 4. Authentication を始める

1. 左のメニューの「構築」から「Authentication」を選び、「始める」を押します。
2. 「ログイン方法」のタブで、「メール / パスワード」を選び、一番上のスイッチを**有効**にして「保存」を押します（下の「メールリンク」はオフのままです）。
3. 「ログイン方法」の画面に戻り、「新しいプロバイダを追加」を押して「匿名」を選び、**有効**にして「保存」を押します。

## 5. 先生のアカウントを作る

1. Authentication の「ユーザー」のタブを開き、「ユーザーを追加」を押します。
2. 自分のメールアドレスとパスワードを入れて「ユーザーを追加」を押します。これが先生のアカウントです。
3. 一覧に出た自分の行の「ユーザー UID」（英数字の長い文字）を**控えます**。

## 6. 先生として許可する

先生のアカウントだけが授業を作れるように、UID を登録します。

1. Realtime Database の「データ」のタブを開きます。
2. データベース名（URL の行）の右にある「＋」を押します。
3. 「名前」に `teacherList`、「値」は空のままにして、「＋」で下の階層を作ります。
4. 「名前」に、控えておいた UID を入れ、「値」に `true` と入れて「追加」を押します。

できあがりは、次のような形です。

```
teacherList
  └ （自分の UID）: true
```

## 7. Web API キーを控える

1. 左上の「プロジェクトの概要」の横の歯車を押し、「プロジェクトの設定」を開きます。
2. 「全般」のタブにある「ウェブ API キー」を**控えます**。

「ウェブ API キー」の欄が無い、または「マイアプリ」にアプリの登録を求められるときは、次のようにウェブアプリを 1 つ登録します（無料で、何もインストールしません）。

1. 同じ「全般」のタブを下へ進み、「マイアプリ」の所にある **`</>`（ウェブ）** のアイコンを押します。
2. 「アプリのニックネーム」に `classpulse` など好きな名前を入れます。「Firebase Hosting も設定します」のチェックは**入れません**。
3. 「アプリを登録」を押します。
4. 「Firebase SDK の追加」という画面に、`apiKey: "AIza..."` という行が出ます。この `"` と `"` の間の文字が、ウェブ API キーです。**控えます**。画面に出ているコードを貼ったり、コマンドを実行したりする必要はありません。
5. 「コンソールに進む」を押して閉じます。

## 8. Claude Code に伝える

次の 2 つを Claude Code に伝えてください。

- データベースの URL（手順 2）
- ウェブ API キー（手順 7）

データベースの URL とウェブ API キーは、公開してよい値です。**パスワードは Claude Code に伝えないでください。** ログインして確かめる作業は、先生が自分のブラウザで行います（Claude Code は、手元のパソコンの中だけで動く練習用のデータで画面を確かめます）。

## 9. ルールの確かめ方

ルールが守ってくれているかを、Firebase の画面で試せます。

1. Realtime Database の「ルール」のタブで「ルール プレイグラウンド」を開きます。
2. まず、「認証済み」のスイッチを**オフ**にして、次の 4 つを試します。「シミュレーションの種類」で「読み取り」か「書き込み」を選び、「場所」に下の文字を入れ、書き込みのときは「データ」も入れて「実行」を押します。

| 種類 | 認証 | 場所 | 送るデータ | 期待する結果 |
| --- | --- | --- | --- | --- |
| 読み取り | なし | `/sessions/x/inbox/answers` | （なし） | 拒否される |
| 読み取り | なし | `/teachers/abc` | （なし） | 拒否される |
| 書き込み | なし | `/sessions/x` | `{"owner":"abc"}` | 拒否される |
| 読み取り | なし | `/teacherList/abc` | （なし） | 拒否される |

3. 次に、「認証済み」のスイッチを**オン**にします。「プロバイダ」は「匿名」を選び、「Firebase UID」の欄に、表の「UID」の文字を入れて試します。`student1` は先生ではない生徒の代わりの名前で、`teacherList` には入っていません。

| 記号 | UID | 種類 | 場所 | 送るデータ | 前にあるべきデータ | 期待する結果 |
| --- | --- | --- | --- | --- | --- | --- |
| a | `student1` | 読み取り | `/sessions/x/inbox/answers` | （なし） | なし | 拒否される |
| b | `student1` | 書き込み | `/sessions/x/inbox/answers/s1/student2` | `{"choice":0,"at":0}` | なし | 拒否される |
| c | `student1` | 書き込み | `/sessions/newid` | `{"owner":"student1"}` | なし（`student1` は `teacherList` に入っていない） | 拒否される |
| d | `student1` | 読み取り | `/teachers/someoneelse` | （なし） | なし | 拒否される |
| e | `student1` | 書き込み | `/sessions/x/inbox/answers/s1/student1` | `{"choice":0,"at":0}` | 授業 `x` が無い（質問が受付中ではない） | 拒否される |
| f | 自分の先生の UID（手順 6 で `teacherList` に入れたもの） | 読み取り | `/teachers/（自分の UID）` | （なし） | `teacherList` に自分の UID がある | 許可される |

e は「授業が無いときは回答を書けない」ことの確認です。「受付中は書けて、締め切ったあとは書けない」ことは、ここでは確かめられません（下の注意を見てください）。

自由記述の回答（`text`）が 200 文字をこえると拒否されること、`choice` と `text` をいっしょに送ると拒否されることは、プレイグラウンドでは確かめられません（質問の種類を授業のデータから読むため）。アプリができたあとに、アプリで確かめます。
空白だけの `text`（例: `"   "`）も規則で拒否します（`matches(/\S/)`）。これもプレイグラウンドではなく、アプリで確かめます。
ワードクラウドの回答（`words`: 1〜3 個、それぞれ 1〜20 文字で空白だけでない文字列。鍵は `0`・`1`・`2` だけ）も、4 個目・21 文字・空白だけ・`choice` や `text` といっしょのものを規則で拒否します。これもアプリで確かめます（ワードクラウドを足したときに規則を変えたので、ルールを貼り直してください）。

「拒否される」は赤、「許可される」は緑で表示されます。期待と違うときは、ルールの貼り間違いかもしれません。手順 3 をやり直してください。

**注意:** 「受付中の本人の回答は通り、締め切ったあとは拒否されること」は、授業のデータと、サーバーの時刻（回答の `at`）が必要なので、このプレイグラウンドでは確かめられません。アプリができたあとの通し確認（計画の Task 13 の 1・3・4・5）で、本物のアプリと本物のデータベースを使って確かめます。それが済むまでは、この点は「未確認」です。

## 管理者を登録する（1 回だけ）

アプリの「先生の管理」の画面を使えるのは、管理者だけです。管理者は、Firebase の画面で次のように登録します。

1. 手順 3 と同じやり方で、最新の `docs/firebase/rules.json` をルールに貼って「公開」を押します（先生の管理のための規則が入っています）。
2. Realtime Database の「データ」のタブを開きます。
3. いちばん上の行（データベースの URL の行）にマウスをのせて「＋」を押します。
4. 「キー」に `admins` と入れます。その右の「＋」を押して、下にもう 1 行を作ります。
5. 下の行の「キー」に**自分の UID**（手順 6 で `teacherList` に入れたものと同じ）を入れ、「値」に `true` と入れます（引用符は付けません）。
6. 「追加」を押します。`admins` の下に、自分の UID と `true` が並んでいれば完了です。
7. アプリを読みこみ直すと、左のメニューに「先生の管理」が出ます。

管理者を増やすときも、同じように `admins` の下に、その先生の UID を `true` で足します。

## Google アカウントでログインできるようにする（1 回だけ）

「Google でログイン」のボタンを使うための設定です。どれも無料で、支払いの登録はいりません。画面の言葉は、時期によって少し違うことがあります。迷ったら、画面の写真を Claude Code に見せてください。

### A. Firebase で Google のログインを有効にする

1. Firebase コンソールで、左のメニューの「Authentication」→「ログイン方法」（Sign-in method）のタブを開きます。
2. 「新しいプロバイダを追加」を押し、「Google」を選びます。
3. 「有効にする」のスイッチをオンにします。「プロジェクトのサポートメール」で自分のメールアドレスを選びます。
4. 「保存」を押します。
5. 一覧に出た「Google」の行をもう一度開きます。「ウェブ SDK 構成」を開くと、「ウェブ クライアント ID」が出ます（`数字-英数字.apps.googleusercontent.com` の形）。これを**控えて、Claude Code に伝えます**（公開してよい値です。その下の「ウェブ クライアント シークレット」は**伝えないでください**。使いません）。

### B. Firebase に、アプリの場所を登録する

1. 「Authentication」→「設定」のタブ →「承認済みドメイン」を開きます。
2. 「ドメインの追加」を押し、`schooldatahuruyama-lgtm.github.io` を入れて追加します。

### C. Google に、ログインのあとに戻ってよい場所を登録する

1. https://console.cloud.google.com/ を開きます（Firebase と同じ Google アカウントで）。
2. 画面の上のプロジェクトの名前を押して、Firebase と同じプロジェクト（`classpulse-slide`）を選びます。
3. 左上の「≡」→「API とサービス」→「認証情報」を開きます。
4. 「OAuth 2.0 クライアント ID」の一覧にある「Web client (auto created by Google Service)」を押します（A の 5 で控えたクライアント ID と同じものです）。
5. 「承認済みの JavaScript 生成元」の「URI を追加」を押し、`https://schooldatahuruyama-lgtm.github.io` を入れます。
6. 「承認済みのリダイレクト URI」の「URI を追加」を押し、`https://schooldatahuruyama-lgtm.github.io/classpulse/` を入れます（最後の `/` まで、このとおりに）。
7. 「保存」を押します。反映まで数分かかることがあります。

### D. だれでもログインの画面を出せるようにする

1. 同じ Google Cloud の画面で、「API とサービス」→「OAuth 同意画面」（新しい画面では「Google Auth Platform」→「対象」）を開きます。
2. 「公開ステータス」が「テスト中」なら、「アプリを公開」を押して「本番環境」にします。このアプリが受け取るのはメールアドレスだけなので、Google の審査はいりません。
   - 「テスト中」のままだと、「テストユーザー」に登録した人しかログインできません。
   - 「ユーザーの種類」が「内部」になっている場合は、同じ組織（学校や自治体）のアカウントだけがログインできます。個人のアカウントでも使うなら「外部」にします。

### E. ルールを貼り直す

手順 3 と同じやり方で、最新の `docs/firebase/rules.json` を貼って「公開」を押します（Google で入った人も、利用を申しこめるようにする変更が入っています）。

### うまくいかないとき

- Google の画面に「このアプリのリクエストは無効です」「redirect_uri_mismatch」と出る: C の 6 の URL が 1 文字でも違うと出ます。`https://` から最後の `/` までを確かめてください。
- Google の画面に「アクセスをブロック: 組織の管理者が…」のように出る: そのアカウントを管理している人（学校や自治体）が、外のアプリへのログインを止めています。アプリの側では変えられません。個人のアカウントか、メールアドレスとパスワードでのログインを使ってください。
- アプリに戻ったあと「Google でログインできませんでした。」と出る: A の「有効にする」がオンになっているか、Claude Code に伝えたクライアント ID が A の 5 のものと同じかを確かめてください。

## 先生を増やすとき

1. 新しい先生に、アプリのログイン画面の「はじめて使う先生はこちら」から、自分のメールアドレスとパスワードで登録してもらいます。
2. 管理者が、アプリの「先生の管理」を開きます。「承認待ち」に、その先生のメールアドレスが出ます。
3. 本人に「いま登録しましたか」と確かめてから、「承認する」を押します。

知らないメールアドレスが並んでいたら、「ことわる」を押します。

先生をやめてもらうときは、「先生の管理」でその先生の「利用を停止」を押します。教材と授業の記録は消えません。「再開」で元に戻せます。

（「先生の管理」を使わずに、今までどおり Firebase の画面で `teacherList` に UID を足す・消すこともできます。）

### うまくいかないとき

- 登録の画面で「いまは登録できません。」と出る: Firebase の Authentication の設定で、新しい登録が止められています。Authentication →「設定」→「ユーザー アクション」の「作成（登録）を許可する」にチェックが入っているかを確かめてください。
- 「先生の管理」がメニューに出ない: `admins` の下の UID が、自分の UID と同じかを確かめてください。ルールを貼り直したかも確かめてください。
