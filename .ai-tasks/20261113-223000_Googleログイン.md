# 実装指示書: Google アカウントでのログイン

**設計書（先に全部読むこと。流れ・文・規則は、設計書のとおりに）:** `docs/superpowers/specs/2026-11-13-google-login-design.md`

**Goal:** ログイン画面と登録の画面に「Google でログイン」を足す。SDK を使わず、ID トークンを URL のフラグメントで受け取って、Firebase の REST（`accounts:signInWithIdp`）でログインする。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、REST だけ、`npm test`（今 654 件が通っている）。

## Global Constraints

- 外部のスクリプト・スタイルを読みこまない。`index.html` に外部 URL を足さない（Google へは、ページの移動と `fetch` だけ）。
- ID トークンを、`localStorage`・`sessionStorage`・URL・履歴・ログ・エラー文に残さない。`sessionStorage` に入れるのは `{ state, nonce, at }` だけで、戻ってきたらすぐ消す。
- `FIREBASE.googleClientId` が空（今の値）のときは、ボタンを出さず、Google の戻りも処理しない。今までのふるまいが 1 つも変わらないこと。練習モードでも出さない。
- 今あるコードの書き方に合わせる（日本語のコメント、`el()`、`innerHTML` を使わない、通信や乱数や時計は引数で受け取ってテストできる形にする）。
- `js/session-*.js`、`js/outbox.js`、`js/model.js`、`js/repo.js`、編集・発表・生徒の画面を変えない。
- 今あるテストを壊さない。git の操作はしない。パッケージを足さない。

## Review Focus（必ずテストで押さえる）

1. `state` が合わない・`nonce` が合わない・保存が無い・10 分をこえた戻りでは、`signInWithIdp` を呼ばない。
2. 戻りを処理するとき、まずハッシュを置きかえてから、ほかのことをする（途中で失敗しても、トークンが URL に残らない）。
3. 関係のないハッシュ（`#/login`、`#/edit/abc`、`#/join/xyz`、`#id_tokenx`、空）を、Google の戻りとまちがえない。生徒の参加の URL の動きを変えない。
4. こわれた ID トークン（点が 2 つ無い、base64 でない、JSON でない、`nonce` が無い）で、例外が外へ出ない（「確かめられませんでした」になる）。
5. `signInWithIdp` の応答に `needConfirmation: true` があるとき、ログインした状態にしない（保存もしない）。

## 作るもの

### 1. `js/google-login.js`（新しい。純粋な関数。ブラウザの物は引数で受け取る）

- `randomToken(getRandomValues): string` … 16 バイト以上の乱数を、URL に使える文字（英数字と `-` `_`）で。
- `buildGoogleAuthUrl({ clientId, redirectUri, state, nonce }): string` … 設計書 3 章 2 の URL（`URLSearchParams` で組み立てる）。
- `redirectUriFrom(location): string` … `origin + pathname`。
- `parseGoogleCallback(hash): { idToken, state } | { error, state } | null` … Google の戻りでなければ `null`。`#/` で始まるハッシュは必ず `null`。
- `jwtPayload(token): object | null` … JWT の 2 つ目の部分を base64url で読んだ中身。読めなければ `null`（例外を投げない）。署名は確かめない（確かめるのは Firebase のサーバー。ここでは `nonce` を読むだけ、とコメントに書く）。
- `checkGoogleCallback({ saved, parsed, now, maxAgeMs }): { ok: true, idToken } | { ok: false, reason: 'cancelled' | 'mismatch' }` … `error === 'access_denied'` は `'cancelled'`、ほかの `error`・保存なし・時間切れ・`state` ちがい・`nonce` ちがい・読めないトークンは `'mismatch'`。
- `CONFIG.googleLogin = { maxAgeMs: 600000, storageKey: 'classpulse:google-login' }` を `js/config.js` に足す。
- テスト: 新しい `tests/google-login.test.js`。

### 2. `js/auth.js`・`js/errors.js`

- `signInWithGoogleIdToken(idToken, requestUri): Promise<{ uid, email }>`（`role: 'teacher'` だけ）。`accounts:signInWithIdp` に設計書 3 章 4 の中身を送る（`postBody` は `URLSearchParams` で組み立てる）。成功は `signInTeacher` と同じように採用・保存する。
- 失敗の `NetError` の `code`: 応答に `needConfirmation: true`、または `EMAIL_EXISTS`・`FEDERATED_USER_ID_ALREADY_LINKED` → `'account-exists'`（ログインした状態にしない）、通信 → `'network'`、ほか → `'google-failed'`。サーバーの生のエラー文は残さない（`signUpTeacher` と同じ考え方）。`js/errors.js` の一覧に足す。
- 練習モードの auth（`js/dev/demo.js`）には、`signInWithGoogleIdToken` を「使えません」の例外で足す。
- テスト: `tests/auth.test.js` に足す（送る中身、保存に ID トークンの文字が無い、`needConfirmation`、失敗の種類、生徒の auth では使えない、応答を待つ間にログアウトしたら採用しない＝今の `gen` の考え方）。

### 3. 起動時の戻りの処理と、ボタン（`js/firebase-config.js`、`js/main.js`、`js/views/login.js`、`js/views/signup.js`、`css/app.css`）

- `js/firebase-config.js`: `googleClientId: ''` を足し、冒頭のコメントに「Google ログインのクライアント ID（公開してよい値）」を足す。今ある 2 つの値は変えない。
- `main.js`: `start()` の中で、最初の `render()` より前に、Google の戻りを処理する。順番は設計書 3 章 4 のとおり（ハッシュの置きかえが最初）。処理の本体は、テストできるように `js/google-login.js` か新しい小さなモジュールに、引数（`location` の代わり、`history.replaceState` の代わり、`sessionStorage`、`auth`、時計、クライアント ID）を受け取る関数 `handleGoogleCallback(deps): Promise<{ handled: boolean, notice?: string }>` として置き、`main.js` はそれを呼ぶだけにする。`notice` は、ログイン画面の `ctx.notice`（今も `login.js` が読んでいる）で出す。成功したら、そのまま今の `render()` に任せる（ハッシュは `#/login` になっているので、使える先生はホームへ、まだの人は承認待ちへ送られる）。
- 練習モード（`backend.demo` があるとき）とクライアント ID が空のときは、戻りを処理しない（ハッシュにも触らない）。
- `ctx` に `googleLogin`（押したときに呼ぶ関数。クライアント ID が空・練習モードなら `null`）を渡す。`login.js` と `signup.js` は、`ctx.googleLogin` があるときだけ、設計書 4 章のボタンと文を出す。押したら、ボタンを押せなくして `ctx.googleLogin()` を呼ぶ（`state`・`nonce` を作って保存し、`location.assign` で移る。これも引数を受け取る関数にしてテストする）。
- テスト: 戻りの処理（成功、やめた、`state` ちがい、時間切れ、クライアント ID が空なら何もしない、ハッシュの置きかえが `signInWithGoogleIdToken` より前）、ボタンを押したときに保存される中身と移動先の URL。

### 4. 規則（`docs/firebase/rules.json`、`tests/rules.test.js`）

- 設計書 3 章「規則」の 1 か所だけを変える。テストの期待値を合わせる（`teacherRequests` の `.write` に `auth.provider !== 'anonymous'` があり、`'password'` が無い。ほかの規則の文字列が変わっていない）。
