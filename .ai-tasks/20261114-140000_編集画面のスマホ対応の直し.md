# 実装指示書: 編集画面のスマホ対応の直し（レビュー round 1 の 2 件）

**レビュー:** `.ai-review/20261114-123741_round1.md`　**設計書:** `docs/superpowers/specs/2026-11-14-editor-phone-design.md`
**前の指示書:** `.ai-tasks/20261114-130000_編集画面のスマホ対応.md`（守ること・変えてよいファイルは同じ。git の操作はしない）

## 直すもの

1. **文字を入れたあと、「要素を選ぶ」の一覧の抜粋が古い。** 文字の入力を終えたとき（`finishEdit`）と、設定のパネルを開くとき（`ed.openSettings`・下の帯の「設定」）に、右の列の中身を最新のデータで描き直す。入力中は、入力欄を作り直さない（打つたびに右の列を描き直さない）。幅 900px 以上の動きは変えない。
2. **幅を変えたあとにスライドのパネルを開くと、選んでいるスライドが見えない。** パネルを開いて見えるようになったあとにも、選んでいるスライドの縮小表示を、一覧の中で見える位置へ動かす。ページ全体はスクロールさせない。

## 端の場合

| 場合 | 動き | テスト |
|---|---|---|
| 文字を追加 → 入力 → 「できた」 → 「設定」 | 一覧に「文字: （入れた文字の先頭 12 文字）」 | 自動 |
| 入力を、別の要素のタップ・Esc・スライドの切りかえで終えた | 同じく最新。消えた要素の行は出ない | 自動 |
| 空にして終えた・不正な値（`text` が文字でない） | 「文字: （空）」 | 自動 |
| 設定のパネルを開いたまま入力した（入力中はパネルが隠れる） | 終わってパネルを開き直すと最新 | 自動 |
| 同じ文字のまま終えた（重複） | 描き直してよい。フォーカスは「文字を入力」ボタンへ戻る（今のまま） | 自動 |
| スライドが多い（20 枚）・最後を選んでいる・幅を広い → せまいにしてからパネルを開く | 選んでいる縮小表示が一覧の見える範囲に入る。`window` のスクロール位置は変わらない | 自動 |
| スライド 0 枚・1 枚 | 何もしない。例外にしない | 自動 |
| 失敗の見せ方 | 新しい失敗の文は無い | — |

`npm test` がすべて成功すること（今 1243 件）。
