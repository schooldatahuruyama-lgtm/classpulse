# 実装指示書: PowerPoint（.pptx）の直接取りこみ

**設計書（先に全部読むこと。取りこむもの・数え方・画面の文・上限は、設計書のとおりに）:** `docs/superpowers/specs/2026-11-14-pptx-import-design.md`

**参考にする今のコード:** `js/pdf-import.js`、`js/pdf-import-logic.js`、`js/views/dashboard.js`（PDF の取りこみの流れ・進みぐあい・やめる・失敗の出し方）、`js/image.js`（`compressImage`）、`js/model.js`（`createTextItem`・`clampItem`・文字の要素の項目）。

**Goal:** ホームの「PowerPoint から作る」で `.pptx` を選ぶと、文字と画像を編集できる要素として持つ教材ができる。取りこめなかったものの数を知らせる。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、`npm test`（今 942 件が通っている。Node の `DecompressionStream`・`zlib` をテストで使ってよい）。

## Global Constraints

- パッケージ・外部のライブラリを足さない。ファイルと中身を外へ送らない。外部への参照を読みに行かない。
- ZIP・XML・スライドの読み取りは、DOM に触れない純粋なモジュールにし、Node でテストする（`DOMParser` を使わない）。ブラウザの部品（`Image`・`canvas`・`Blob`）を使うのは `js/pptx-import.js` と、今ある `js/image.js` だけ。
- PowerPoint の読み取りの部品は、「PowerPoint から作る」を初めて押したときに読みこむ（ホームのモジュールから静的に読みこまない。PDF と同じ）。
- 今ある PDF の取りこみ・ホームのほかの動き・`js/model.js` の今ある関数の動きを変えない。`docs/firebase/rules.json` を変えない。
- 今あるコードの書き方に合わせる（日本語のコメント、`el()`、`innerHTML` を使わない、失敗は `{ code }` を持つ Error）。今あるテストを壊さない。git の操作はしない。

## Review Focus（必ずテストで押さえる）

1. 悪いファイルで固まらない・例外が外へ出ない: 末尾がこわれた ZIP、中央ディレクトリの位置や長さがファイルの外、展開すると上限をこえる項目（小さく圧縮された大きなデータ）、暗号化の印、`<!DOCTYPE` のある XML、とても深い入れ子、自分を指すグループ・レイアウトの参照。どれも「読めない」の失敗になる。
2. 参照先が `ppt/` の外（`../../x`、`/x`）・外部（`TargetMode="External"`）の画像を読まない（「画像」として数える）。
3. 文字に `<script>`・`&lt;img onerror&gt;` が入っていても、そのままの文字として要素に入る（HTML にしない）。作った教材は `normalizeDeck` を通しても変わらない。
4. 位置の計算: ふつうの箱、レイアウトから受けつぐ箱、どこにも無いときの既定、グループの中（入れ子も）、4:3 のスライド。どの要素も 0〜1 の枠の中に収まる。大きさ 0 のグループで割り算がこわれない。
5. 途中でやめた・失敗したときに、教材を保存しない。やめたあとに終わった処理が、画面に何も出さない。

## 作るもの

1. `js/zip-read.js` と `tests/zip-read.test.js`（設計書 3.1）。`openZip(bytes: Uint8Array, limits)` → `{ has(name), names(), read(name, maxBytes): Promise<Uint8Array> }` のような形。展開は `DecompressionStream('deflate-raw')`（無ければ `{ code: 'unsupported' }`）。
2. `js/xml-read.js` と `tests/xml-read.test.js`（設計書 3.2）。
3. `js/pptx-import-logic.js` と `tests/pptx-import-logic.test.js`（設計書 3.3）。ZIP の読み手を引数で受け取り、`{ title, slides: [{ items: [文字の要素 | { kind: 'image', x, y, w, h, media: '<項目の名前>' }] }], skipped: { shape, chart, line, image, other, hiddenSlide } }` のような、画像を変える前の形を返す関数と、まとめの文・失敗の文・ファイルの検査・教材の組み立て（`buildDeckFromPptx`）。上限は `CONFIG.pptx`（`js/config.js`）。
4. `js/pptx-import.js`（設計書 3.4）。`importPptx(file, { onProgress, signal })`。画像の変換は `compressImage`（項目のバイト列から、拡張子で決めた `type` の `Blob` を作って渡す）。
5. `js/views/dashboard.js`・`css/app.css`: 設計書 4 章。PDF の取りこみと同じ流れ（同時に 1 つだけ。取りこみ中は、もう一方のボタンも押せない）。
6. テスト用の .pptx は、テストの中で組み立てる（`tests/helpers/` に、名前と中身の表から ZIP を作る小さな関数を置いてよい）。リポジトリにバイナリのファイルを足さない。
