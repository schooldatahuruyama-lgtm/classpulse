# 実装指示書: 不適切な言葉の自動チェックと、確かめてから映す

**設計書（先に全部読むこと。言葉の一覧・画面の文・データの形は、設計書のとおりに）:** `docs/superpowers/specs/2026-11-14-auto-check-design.md`

**Goal:** 自由記述・ワードクラウドで、言葉の一覧に当たった回答を「確認待ち」として教室の画面に出さない。先生は、発表の画面で確認待ちを出して 1 件ずつ「映す」ことができ、授業のあとは結果の画面と CSV で読める。先生の設定の画面「止める言葉」を足す。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、REST だけ、`npm test`（今 819 件が通っている）。

## Global Constraints

- 外部のスクリプト・スタイル・サービスを使わない。生徒の文章を、データベースと先生の端末のほかへ送らない。
- `docs/firebase/rules.json` を変えない。生徒の画面（`js/views/student.js`、`js/session-client.js`、`js/outbox.js`）を変えない。
- 発表の画面の今までの決まりを守る: 文章・言葉は `textContent` でだけ入れる。uid・言葉の鍵を DOM（属性・id・dataset）に入れない。結果を表示する前は、文章・言葉の要素を作らない。
- 確認待ちの文章・言葉は、host の状態（`onChange` に渡す物）に入れない。`host.heldItems()` を呼んだときだけ返す。
- 今あるコードの書き方に合わせる（日本語のコメント、`el()`、`innerHTML` を使わない、通信・時計・保存先は引数で受け取ってテストできる形）。
- 今ある関数の引数は、後ろに足す形で広げる（`freeList(answers, hidden)` を今までどおり呼んだら、今までと同じ結果に `heldItems: []` が足されるだけ）。今あるテストは、`heldItems`・`heldCount`・`heldTexts`・`heldWords` が足されたことによる期待値の直しのほかは、変えずに通ること。
- git の操作はしない。パッケージを足さない。

## Review Focus（必ずテストで押さえる）

1. 確認待ちの一覧を出す前、発表の画面の DOM と host の状態に、確認待ちの文章・言葉が 1 文字も無い。
2. 確認待ちの一覧を開いている間に届いた新しい確認待ち・書き直された文章が、一覧に足されない・書きかわらない（書き直された 1 件は消えるだけ）。
3. 自由記述で「映す」を押したあとに生徒が書き直すと、当たりなら確認待ちに戻る（`released[uid]` が今の文章と同じときだけ効く）。先生がかくした回答は、当たりでも「映す」済みでも、かくした回答のまま。
4. ふつうの言葉が当たらない: 「やくそく」「ばかり」「イエロー」「パチンコ」「暗殺した」「カステラ」。当たる: 「死ね」「し ね よ」は「しねよ」として当たる、「ＦＵＣＫ」、「バ・カ」、「うぜー」。
5. 設定を読めない・こわれているときは `{ enabled: true, words: [] }` で動く（例外で発表の画面が止まらない）。`release` の保存が失敗しても、手元では映したままで、Promise は拒否される。

## 作るもの

### 1. `js/moderation.js`（新しい。純粋な関数）と `tests/moderation.test.js`

- `BUILTIN_WORDS`（設計書 3 章の一覧をそのまま。配列）
- `normalizeForCheck(text): string`
- `normalizeWordList(raw): string[]`（設計書 3 章。上限は `CONFIG.moderation = { maxWords: 100, maxWordLength: 20, minCheckLength: 2 }` を `js/config.js` に足す）
- `normalizeModeration(raw): { enabled, words }`
- `createChecker(settings): (text) => boolean`（はじめから入っている言葉 ＋ `settings.words`。文字列でない入力は `false`）

### 2. `js/session-logic.js`

- `freeList(answers, hidden, { isFlagged, released } = {})` → `{ items, hiddenItems, heldItems, total }`。`heldItems` も `{ uid, text }` で、並びは今までと同じ決まり。
- `cloudList(answers, hidden, { isFlagged, released } = {})` → 同じく `heldItems`（`{ key, word, count }`）。その鍵の、どれかの形が当たれば当たり。
- `buildHistory(session, inbox, endedAt, hidden, quiz, { isFlagged, released } = {})`。`released` は `{ <slideId>: { <鍵>: 文字列 | true } }`。自由記述に `heldTexts`、ワードクラウドに `heldWords` を足す（uid・鍵は入れない）。
- テスト: `tests/session-logic.test.js` に足す。

### 3. `js/repo.js`

- `getModeration(): Promise<{ enabled, words }>`（`teachers/<uid>/settings/moderation` を読み、`normalizeModeration` で正す）
- `saveModeration({ enabled, words }): Promise<void>`（正してから書く）
- `normalizeQuestion`: 自由記述に `heldTexts`、ワードクラウドに `heldWords`（無ければ空の配列）。
- テスト: `tests/repo-data.test.js` か `tests/repo.test.js` の今のやり方に合わせて足す。

### 4. `js/session-host.js`

- 設計書 5 章のとおり。`start()` で `repo.getModeration()`（失敗は既定値）と `session.host.released` を読む。`released` の正し方は `cleanHidden` にならう（鍵は `validKey`、値は 200 文字までの文字列か `true`）。
- 状態に `heldCount` を足す。`heldItems(slideId)`、`release(slideId, key)` を足す。`release` のあと、表示中の一覧の写し（`listView`）を作り直して、すぐに出るようにする。
- 終了（`finish`）: `host/released` を読み直して手元と合わせ（手元を優先）、`buildHistory` に渡す。
- 今ある「かくす」の動き（再試行、端末への保存、終了のときの扱い）を変えない。
- テスト: `tests/session-host.test.js` に足す。

### 5. `js/views/present.js`・`css/present.css`（発表の画面の CSS がある場所に合わせる）

- 設計書 6.1 のとおり。ボタンの押せる・押せないの決めごとは、今の `pollControls` のように純粋な関数にしてテストする。
- 確認待ちの一覧は、今の QR コードの `dialog` の作り方にならう（`showModal`、閉じたらフォーカスを「確かめる」か、無ければ結果のボタンへ戻す）。キーボードの「次へ」（→・スペース）は、`dialog` が開いている間は今までどおり効かない。
- 「かくす」の確認、雲の言葉の確認（`askHideWord`）など、今ある動きを変えない。
- テスト: `tests/present-view.test.js` の今のやり方に合わせて足す。

### 6. 設定の画面: `js/views/words.js`（新しい）、`js/router.js`、`js/main.js`、`css/app.css`

- ルート名 `words`、ハッシュ `#/words`。先生だけ（今の `trash` と同じ守り方）。ナビゲーションに「止める言葉」を足す（`main.js` の `trash` の近く）。

- テスト: `tests/router.test.js` と、画面の動き（今ある画面のテストのやり方に合わせて、できる範囲で）。

### 7. 結果の画面と CSV: `js/views/history.js`、`js/results-csv.js`
