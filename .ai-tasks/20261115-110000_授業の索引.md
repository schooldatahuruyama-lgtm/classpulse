# 実装指示書: 授業の索引（レビュー round 2 の指摘への対応）

**設計書（8 章を読むこと）:** `docs/superpowers/specs/2026-11-15-teacher-delete-design.md`
**レビュー:** `.ai-review/20261114-095412_round2.md`　**前の指示書:** `.ai-tasks/20261115-090000_停止した先生の削除.md`（守ることは同じ）

**目的:** 記録にも「発表中」の印にも載らない授業が、先生の削除で残らないようにする。授業を作るとき、持ち主ごとの索引 `teachers/<uid>/sessions/<sid>: true` を同じ書きこみで残し、先生の削除はこの索引も見る。

変えるのは `js/session-host.js`（`startSession` だけ）、`js/repo.js`（`deleteTeacher`・`deleteHistory`）、`docs/firebase/rules.json`、それらのテスト（と、授業の開始を通るテスト・`tests/helpers/`・`tools/load-sim.mjs` のうち、この変更で直しが要るもの）。git の操作はしない。

## 作るもの

1. `js/session-host.js` の `startSession`: `net.set('sessions/<sid>', …)` を、`net.update('', { 'sessions/<sid>': 授業, 'teachers/<uid>/sessions/<sid>': true })` 1 回に変える。そのあとの `repo.setActive(…)`、返す値、検査（`validateDeck`）は変えない。
2. `js/repo.js`:
   - `deleteHistory(sid)`: 今の `patch` に `teachers/<uid>/sessions/<sid>: null` を足す。
   - `deleteTeacher(targetUid)`: `net.getKeys('teachers/<targetUid>/sessions')` も読み、`history` の鍵・`active.sid` と合わせる（鍵の形の確かめ・重なりを取る・持ち主の確かめ・6 個ずつ、は今のまま）。
3. `docs/firebase/rules.json` の `teachers.$uid` に、`history`・`active` と同じ文字列の `.read` を持つ `"sessions"` を足す。ほかは変えない。

## 端の場合とテスト

| 場合 | テスト |
|---|---|
| 授業の開始 | `update('', …)` が 1 回で、鍵が `sessions/<sid>` と `teachers/<uid>/sessions/<sid>` の 2 つ。`net.set('sessions/…')` を呼ばない。`update` が失敗したら `setActive` を呼ばず、例外が外へ出る（今の `set` の失敗と同じ） |
| 2 つのタブで同時に始めた（索引に 2 件、`active` は 1 件、`history` は空） | `deleteTeacher` の `patch` に、2 つの授業が両方入る |
| 索引に、ほかの先生の授業の ID | 持ち主の確かめで外れる（今のテストと同じ考え方） |
| 索引が無い（古いデータ） | 今までどおり `history` と `active` から集める |
| 授業の記録を消す | `patch` に索引の項目の `null` がある。今ある項目（履歴・`sessions/<sid>`・`active`）は変わらない |
| 規則 | `teachers.$uid.sessions['.read']` が `history` と同じ文字列。`tests/rules.test.js` の表を合わせる |
| 今ある流れ | 練習用の通信で、授業の開始 → 参加 → 回答 → 終了 → 履歴、が今までどおり通る（`tests/load.test.js` などが通る） |

`npm test` がすべて成功すること（今 1185 件）。
