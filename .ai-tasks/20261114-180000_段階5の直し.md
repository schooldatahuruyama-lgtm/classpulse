# 実装指示書: 段階 5 の直し（Claude Code の確認で見つけた 3 点）

**設計書:** `docs/superpowers/specs/2026-11-14-stage5-resilience-design.md`　**前の指示書:** `.ai-tasks/20261114-170000_段階5_通信の強化と負荷.md`（Global Constraints は同じ）

**Goal:** Service Worker がページの読みこみを壊すおそれを無くす。はじめての端末でも、1 回開けば部品が残るようにする。参加のやり直しで、今までの動きを変えてしまった所を戻す。

変えるのは `sw.js`、`js/sw-logic.js`、`js/main.js`、`js/session-client.js` と、それらのテストだけ。今あるテスト（1122 件）は、下の 3 で動きを戻す所のほかは、期待値を変えずに通ること。git の操作はしない。

## 直すもの

### 1. `sw.js`: ページの移動（`request.mode === 'navigate'`）の取り方【重要】

今は、どの要求も `fetch(request, { cache: 'no-cache' })` で取っている。`mode` が `navigate` の `Request` に、空でない `init` を付けて `fetch`（＝ `new Request(request, init)`）すると、ブラウザによっては `TypeError` になる（古い決まりでは例外、新しい決まりでは `same-origin` に変える。Safari・古い端末でどちらになるかは保証が無い）。例外になると、今のコードは「通信の失敗」とみなしてキャッシュを探し、無ければ失敗を投げるので、**通信がつながっているのに、ページが開けなくなる。**

- ページの移動のときは、`Request` を渡さず、URL から取り直す: `fetch(request.url, { cache: 'no-cache', credentials: 'same-origin', redirect: 'follow' })`（同じ origin の GET であることは、もう確かめてある）。キャッシュに入れる鍵・探す鍵は、今までどおり元の `request`。
- それ以外の要求は、今までどおり `fetch(request, { cache: 'no-cache' })`。
- どちらの場合も、「`fetch` を呼ぶこと自体が同期的・非同期的に例外を投げた」ときに備えて、最後の手段として `fetch(request)`（`init` なし）をもう 1 回だけ試してから、キャッシュへ進む（通信がつながっていれば、必ずネットワークの応答を返せるように）。
- テスト（`tests/sw.test.js`）: 偽の `fetch` が「`navigate` の `Request` オブジェクト ＋ `init`」で呼ばれたら `TypeError` を投げるようにしても、ページの移動でネットワークの応答が返る。ページの移動で `fetch` の第 1 引数が文字列（URL）である。`init` つきの `fetch` が例外でも、`init` なしの `fetch` が成功すれば、その応答が返る（キャッシュの古い写しを返さない）。

### 2. はじめて開いたときに、部品を残す（`js/main.js`、`js/sw-logic.js`）

今は、Service Worker が効きはじめる前に読みこんだ部品（最初の表示に使った `index.html`・JS・CSS・フォント）がキャッシュに入らない。はじめて使う端末は、もう 1 回読みこみ直すまで、通信が切れると開けない。

- 登録のとき、ページがまだ Service Worker に受け持たれていなかった（`navigator.serviceWorker.controller` が `null`）場合だけ、`navigator.serviceWorker.ready` を待ち、さらにページが受け持たれる（`controller` が入る。`controllerchange` を待つ。10 秒待っても入らなければ、やめる）のを待ってから、**もう読みこんである同じ origin の部品を、1 回ずつ取り直す**（Service Worker を通るので、キャッシュに入る）。
  - 取り直す一覧: 今のページの URL（`location.href` の `#` より前）と、`performance.getEntriesByType('resource')` の `name` のうち、同じ origin のもの。重なりは 1 つにする。`sw.js` 自身は入れない。多くても 200 個まで。
  - 一覧を作る所は、`js/sw-logic.js` の純粋な関数（`warmupUrls({ href, origin, entries, max })`）にしてテストする。
  - 取り直しは、4 個ずつ順に（いっせいに 100 個を取りに行かない）。失敗は無視する。応答の中身は読まなくてよい（`fetch(url).then((r) => r.arrayBuffer()).catch(() => {})` のように、最後まで受け取る）。
- もう受け持たれていた場合（2 回目からの読みこみ）は、何もしない（ふつうの読みこみでキャッシュに入る）。
- テスト: `warmupUrls`（ほかの origin を入れない、`#` を取る、重なり、`sw.js` を入れない、上限）。

### 3. `js/session-client.js`: 参加のやり直しで変えてしまった所を戻す

- **参加の書きこみ（`join()`）の失敗で、`start()` 全体をやり直さない・エラーの画面にしない。** 前の動き（失敗は無視して先へ進み、受信がつながったとき（`onStatus('connected')`）に `join()` をもう一度試す）に戻す。理由: (a) 規則に拒否された（授業が終わる瞬間など）だけで「通信できませんでした」の画面になるのは、前より悪い。(b) やり直しのたびに、教材の写し（最大 5MB）を取り直してしまう。
- **やり直しのとき、もう読めている物を取り直さない。** 匿名ログイン（`uid`）は今も 1 回だけ。同じように、教材の写し（`deck`）が読めていれば、次のやり直しでは取り直さない（`pub` は毎回読み直す。授業が終わっていないかを見るため）。
- テスト: 参加の書きこみが `network`・`denied` で失敗しても `phase` が `error` にならず、受信が始まる（`subscribe` が呼ばれる）。つながったときに参加の書きこみがもう一度試される。`pub` の読みこみが 1 回失敗して 2 回目で成功するとき、教材の写しの読みこみは 1 回だけ（教材の写しの読みこみが 1 回失敗したときは、次のやり直しで読む）。前の指示書で足した「参加の書きこみの失敗でやり直す」テストがあれば、この動きに合わせて直す。
