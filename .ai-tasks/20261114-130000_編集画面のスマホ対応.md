# 実装指示書: 編集画面をスマホで使いやすくする

**設計書（全部読むこと。これが正）:** `docs/superpowers/specs/2026-11-14-editor-phone-design.md`（第 3 版）
**相談の記録:** `.ai-review/20261114-120151_round1.md`、`.ai-review/20261114-121040_round2.md`

**目的:** 幅 899px 以下（せまい画面）で、教材の編集画面を指で使いやすくする。幅 900px 以上は、見た目も動きも変えない。

## 守ること

- 変えてよいのは: `css/editor.css`、`js/views/editor.js`、`js/views/editor/canvas.js`、`js/views/editor/inspector.js`、`js/views/editor/slide-list.js`、新しい `js/views/editor/phone-logic.js`（画面に触れない計算だけ。Node でテストできること）、`tests/` の新しいテスト。ほかのファイルを変える必要が出たら、変えずに報告に書く。
- git の操作はしない。パッケージを足さない。`index.html` の `viewport` は変えない。
- データの形、保存のしかた、ドラッグの計算（`beginGesture`〜`onUp` の座標の式）は変えない。
- 文言は設計書のとおり（やさしい日本語）。入力欄の文字は 16px 以上。押せるものは 44×44px 以上。
- `visualViewport` を使わない。文字の入力欄を `position: fixed` にしない。

## 作るもの（設計書の 3.1〜3.8）

1. `js/views/editor/phone-logic.js`（新規。DOM に触れない）
   - `NARROW_QUERY = '(max-width: 899px)'`
   - `slideBarLabel(order, slideId)` → `'スライド（3／12 枚）'`。0 枚は `'スライド（0 枚）'`。選んでいるものが `order` に無いときは `'スライド（12 枚）'`。
   - `quickActions(item)` → `[]`（選んでいない）／`['type', 'settings', 'deselect']`（文字）／`['settings', 'deselect']`（画像・図形）
   - `itemRows(items, selectedId)` → 重なりの上から順の `[{ id, label, selected }]`。`label` は「文字: 先頭 12 文字」（改行と続く空白は空白 1 つに。12 文字をこえたら「…」を付ける）、「文字: （空）」、「画像」、「図形: 四角」など（図形の名前は `inspector.js` の `SHAPE_NAMES` と同じもの。重ねて持たないよう、置き場所を考える）。
   - `nudge(item, dir)` → `dir` は `'left' | 'right' | 'up' | 'down'`。0.01 ずつ動かし、`clampItem` で止める。知らない `dir` は元のまま。
   - `shouldMoveOnDown({ narrow, pointerType, wasSelected })` → 幅が広い、または `pointerType === 'mouse'`、または選んでいた、のどれかなら `true`。
   - `shouldCloseSlidePanel(action)` → `'select' | 'add' | 'duplicate'` は `true`、`'up' | 'down' | 'delete'` は `false`。
2. `js/views/editor.js`: 上の帯（3.1）、下の帯とパネルの外わく（3.2）、幅が 900px をまたいだときの後始末、資料以外のスライドでの右の列（3.7）、下の余白（帯＋開いているパネル）。左右の列は、外わく（見出し＋「閉じる」）と中身の `div` に分け、今の描き直しは中身だけに行う。幅 900px 以上では、外わくの見出しと「閉じる」は出さず、今と同じ見た目にする。
3. `js/views/editor/slide-list.js`: パネルの中の並び、「＋ スライドを追加」の開閉（3.3）。幅 900px 以上は今の並びのまま。
4. `js/views/editor/canvas.js`: すぐ使うボタンの行（3.4）、キャンバスの上の入力欄（3.5）、「選んでから動かす」（3.6）。幅 900px 以上の入力（キャンバスの中の `textarea`、blur で終わる）は今のまま。
5. `js/views/editor/inspector.js`: 「要素を選ぶ」の一覧と「位置を少し動かす」（3.6。せまい画面だけ出す。出す・出さないは CSS でよい）。
6. `css/editor.css`: 今の `@media (max-width: 899px)` を置きかえる。`touch-action` は 3.6 のとおり（せまい画面だけ。幅 900px 以上は今の `none` のまま）。選択肢の行（3.7）、キャンバスの余白 16px（3.8）。

## 端の場合（設計書 5 章の表のとおり。それぞれテストか、報告での確かめを付ける）

| 場合 | 動き | テスト |
|---|---|---|
| 不正な入力: `slideBarLabel` に空の `order`、無い `slideId`、`null` | 上の決まりの文字を返す。例外にしない | 自動 |
| 不正な入力: `itemRows` に `null`・配列でないもの・`kind` が知らない要素・`text` が文字でない | 空の配列／知らない要素は「要素」／文字でない `text` は空として扱う | 自動 |
| 不正な入力: `nudge` に知らない `dir`、はみ出した要素 | 元のまま／`clampItem` で中へ | 自動 |
| 境界: 文字がちょうど 12 文字・13 文字・絵文字（サロゲートペア）・改行だけ | 12 は「…」なし、13 は「…」あり、絵文字を途中で切らない、改行だけは「（空）」 | 自動 |
| 境界: 端での `nudge`、連打 | 端で止まる。同じ値を返す | 自動 |
| 重複: 同じ要素を一覧で 2 回押す | 選んだまま。何も変わらない | 自動（`selected`） |
| 指・ペンで選んでいない要素をなぞる | 動かない。`pointercancel` で選ばない | 自動（`shouldMoveOnDown`）＋報告 |
| マウス・幅 900px 以上 | 今のまま、すぐ動く | 自動 |
| 文字の入力中に、要素が消えた・スライドが変わった・幅が広がった・画面を離れた | 入力欄を閉じる。消えた要素へ書かない。例外にしない | 報告（どの関数で後始末するか） |
| 日本語の変換中 | 入力欄を作り直さない | 報告 |
| パネルを開いたまま描き直し | 外わく・フォーカス・スクロールが残る | 報告 |
| 失敗の見せ方 | この変更で新しい失敗の文は増やさない。保存の失敗は、今の「保存できませんでした」と「もう一度保存」を、上の帯の 2 段目に読める形で出す | 報告 |

`npm test` がすべて成功すること（今 1194 件。新しいテストを足す）。

## 報告に必ず書くこと

- 変えたファイルと、それぞれ何を変えたか。足したテストと `npm test` の件数。
- 設計書のとおりにできなかった所、迷って決めた所。
- 幅 900px 以上で変わった所が無いと言える理由（どのセレクタ・どの分かれ道で守っているか）。
- 文字の入力の後始末を、どの関数にまとめたか。
