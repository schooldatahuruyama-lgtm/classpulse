# 実装指示書: 停止した先生の削除の直し（レビュー round 1 の #1）

**設計書（直してある。3 章の「レビューのあとで追加」と 4 章の `sessions/$sid` を読むこと）:** `docs/superpowers/specs/2026-11-15-teacher-delete-design.md`
**レビュー:** `.ai-review/20261114-094506_round1.md`　**前の指示書:** `.ai-tasks/20261115-090000_停止した先生の削除.md`（守ることは同じ）

**目的:** 先生を削除するとき、ほかの先生の授業（`sessions/<sid>`）を消さないようにする。停止される前の先生は、自分の `history`・`active` に好きな授業の ID を書けるため。

変えるのは `js/repo.js`、`docs/firebase/rules.json`、それらのテストだけ。git の操作はしない。

## 直すもの

1. `docs/firebase/rules.json` の `sessions.$sid`:
   - `.write` を、設計書 4 章の新しい文字列に置きかえる（1 文字もちがえない）。
   - `"owner": { ".read": "auth != null && root.child('admins').child(auth.uid).val() === true" }` を足す（`pub`・`deck`・`inbox` と同じ並び）。ほかは変えない。
2. `js/repo.js` の `deleteTeacher`:
   - 集めた ID（鍵に使える文字のもの。重なりを取ったあと）のそれぞれについて `net.get('sessions/<sid>/owner')` を読み、値が `targetUid` と同じものだけを `patch` に入れる。ちがう・`null` のものは入れない。
   - 読みこみは 6 個ずつ（いっせいに何百も読まない）。1 つでも失敗したら、例外をそのまま外へ出す（`update` を呼ばない）。
   - 順番: `teacherList` の確かめ → 鍵と `active` → 持ち主の確かめ → `update` 1 回。

## 端の場合とテスト

| 場合 | テスト |
|---|---|
| `history` に、ほかの先生の授業の ID がまざっている | その `sessions/<sid>` は `patch` に入らない。本人の授業と、先生の 4 つの場所は入る |
| `active.sid` が、ほかの先生の授業 | `patch` に入らない |
| 授業がもう無い（`owner` が `null`） | `patch` に入らない |
| `owner` の読みこみが 1 つ失敗（`denied`・`network`） | 例外。`update` を呼ばない |
| 授業が 20 件 | 同時に読んでいる `owner` が 6 個をこえない。20 件とも `patch` に入る |
| 規則 | `sessions.$sid['.write']` と `sessions.$sid.owner['.read']` が設計書の文字列と同じ。`tests/rules.test.js` の表を合わせる。`sessions.$sid` のほかの項目（`.read`・`pub`・`deck`・`inbox`）は変わっていない |

`npm test` がすべて成功すること（今 1174 件）。
