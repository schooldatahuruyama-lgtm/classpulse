# 実装指示書: 先生の追加・利用停止の画面

**設計書（先に全部読むこと。画面の文・データ・規則は、設計書のとおりに）:** `docs/superpowers/specs/2026-11-13-teacher-admin-design.md`

**Goal:** 新しい先生が自分で登録して申しこみ、管理者がアプリの中で承認・ことわる・利用停止・再開をできるようにする。

**Tech Stack:** ビルドなしの HTML/CSS/JS（ES modules）、Firebase は REST だけ、`npm test`（`node --test "tests/*.test.js"`）。今 598 件が通っている。

## Global Constraints

- 今あるコードの書き方に合わせる（日本語のコメント、`el()` で DOM を作る、`innerHTML` を使わない、画面は `mount(root, ctx)` が後片づけの関数を返す、通信は `net` を引数で受け取る）。似た画面として `js/views/trash.js`（一覧と確認つきの操作）と `js/views/login.js`（フォーム）を手本にする。
- パスワードを、保存・ログ・エラー文・テストの期待値以外のどこにも残さない。`storage` に入れるのは今と同じ `{ uid, email, refreshToken }` だけ。
- `js/session-*.js`、`js/outbox.js`、`js/model.js`、`js/slide-render.js`、編集・発表・生徒の画面を変えない。
- 規則は、設計書 3 章の文をそのまま使う（`ADMIN` は展開して書く）。`teachers`、`sessions`、`check` の規則は変えない。
- 今あるテストを壊さない。今のふるまいを変えるのは「先生でないアカウントでログインしたとき」だけ（ログアウトして知らせる → 承認待ちの画面へ送る）。これを見ている今あるテストは、新しいふるまいに合わせて直す。
- git の操作はしない。パッケージを足さない。

## Review Focus（必ずテストか実装で押さえる）

1. 承認されていない人・停止された人が、先生の画面のどれも開けない（URL を直接開いても）。
2. 管理者かどうかの読みこみが拒否された・失敗したとき（古い規則のまま・通信できない）、管理者でないとして扱い、ほかの画面は今までどおり動く。
3. 確かめている間にログインしている人が替わったとき、古い結果で画面を出さない・ログアウトしない（今の `isStillUser` の考え方を保つ）。
4. 承認は 1 回の update で書く（`teacherList` だけ書かれて申しこみが残る、という途中の状態を作らない）。
5. 自分自身を停止できない（画面にボタンが無い。`repo` の関数も、自分の uid なら何もせず例外を投げる）。

## 作るもの

### 1. `js/auth.js`・`js/errors.js`

- `signUpTeacher(email, password): Promise<{ uid, email }>` を足す（`role: 'teacher'` のときだけ使える）。`accounts:signUp` に `{ email, password, returnSecureToken: true }` を送る。成功したら、`signInTeacher` と同じようにログインした状態にして保存する。
- 失敗の `NetError` の `code`: `EMAIL_EXISTS` → `'email-exists'`、`INVALID_EMAIL`・`MISSING_EMAIL` → `'invalid-email'`、`WEAK_PASSWORD…`（前方一致）→ `'weak-password'`、`OPERATION_NOT_ALLOWED`・`ADMIN_ONLY_OPERATION` → `'signup-disabled'`、通信 → `'network'`、ほか → `'unknown'`。`js/errors.js` のコメントの一覧にも足す。
- テスト（`tests/auth.test.js` に足す）: 成功（送る中身、返り値、`storage` にパスワードの文字が無い、`auth.user` が入る）、上の失敗の種類それぞれ、生徒の auth では使えない。

### 2. `js/repo.js`（`createRepo(net, uid)` に足す）

- `teacherStatus(): Promise<'active' | 'suspended' | 'none'>` … `teacherList/<uid>` が `true` / `false` / それ以外。`isTeacher()` は今のまま残す。
- `isAdmin(): Promise<boolean>` … `admins/<uid> === true`。読みこみが失敗（拒否・通信）したら `false`（例外を投げない）。
- `getMyRequest(): Promise<{ email, at } | null>`、`requestAccess(email): Promise<void>`（`teacherRequests/<uid>` に `{ email, at: サーバーの時刻 }` を書く。サーバーの時刻の書き方は、今あるコードで `now` を見る規則に書いている所と同じ方法を使う。`js/session-client.js` か `js/outbox.js` を見ること）。
- 管理者用: `listRequests(): Promise<[{ uid, email, at }]>`（古い順）、`listTeachers(): Promise<[{ uid, email, active, approvedAt }]>`（`teacherList` と `teacherDirectory` を合わせる。`email` が無ければ `''`、`approvedAt` が無ければ `0`。並びは、メールアドレスのある人を先に、メールアドレスの順）、`approveTeacher(targetUid, email, now)`（ルートへの 1 回の update で 3 か所）、`rejectRequest(targetUid)`、`setTeacherActive(targetUid, active)`（`targetUid === uid` なら例外）。
- こわれた値（オブジェクトでない項目、文字列でない `email`）は落とすか空にして、画面をこわさない。
- テスト（新しい `tests/teacher-admin.test.js`。`tests/helpers/fake-net.js` を使う。`tests/trash.test.js` を手本に）: 上のそれぞれ。承認が 1 回の update で、3 つのパスだけを書くこと。`isAdmin` が、`net.get` の失敗で `false` を返すこと。

### 3. 道順と入口（`js/router.js`、`js/guard.js`、`js/main.js`）

- 道順: `signup` ↔ `#/signup`（ログイン不要）、`pending` ↔ `#/pending`、`teachers` ↔ `#/teachers`。画面ファイルは `signup`・`pending`・`teachers`。
- `checkTeacherAccess` の `verdict` を、`'ok'`・`'signed-out'`・`'pending'`（`teacherStatus` が `'none'`）・`'suspended'`・`'offline'` にする（`'not-teacher'` をやめる）。
- `main.js` の `render()`:
  - `signup` は、ログインしていなければそのまま出す。先生として使える人が開いたらホームへ。
  - `verdict` が `'pending'`・`'suspended'` のとき: ログアウトしない。`pending` の画面だけを出す（先生の画面・`login`・`signup` を開こうとしたら `#/pending` へ送る）。`pending` の画面には、骨組み（左のメニュー）を付けない。`ctx` に `auth`、`repo`、`navigate`、`status`（`'pending'` か `'suspended'`）を渡す。
  - `verdict` が `'ok'` の人が `#/pending`・`#/signup`・`#/login` を開いたらホームへ。ログインしていない人が `#/pending` を開いたらログイン画面へ。
  - 左のメニュー: 管理者のときだけ「先生の管理」を足す（「ゴミ箱」の下）。管理者かどうかは `repo.isAdmin()` で確かめ、uid ごとに 1 回だけ読む（画面を移るたびに読まない）。ログインしている人が替わったら読み直す。
  - 今の「確かめている間に人が替わったら使わない」「`offline` のときは今の画面に残す」の動きは保つ。
- テスト: `tests/router.test.js`、`tests/guard.test.js` に足す・直す。

### 4. 画面（新しい `js/views/signup.js`、`js/views/pending.js`、`js/views/teachers.js`。`js/views/login.js` にリンクを足す。`css/app.css` に見た目を足す）

- 文とボタンは、設計書 4 章のとおり。
- `signup.js`: 成功したら `ctx.auth.signUpTeacher` → `createRepo` は `main.js` の持ち物なので、申しこみの書きこみは `ctx.requestAccess(email)` のように `main.js` から渡した関数で行うか、`ctx.net` と `createRepo` を使う（今の `ctx` の作り方に合うほうで）。そのあと `ctx.navigate('pending')`。画面が替わったあとに成功した登録は、黙って残さない（`login.js` と同じ考え方）。
- `pending.js`: 開いたら `getMyRequest()` で申しこみがあるかを確かめて、設計書の 4 通りを出し分ける。「もう一度確かめる」は `ctx.navigate('dashboard')`（承認されていればホームが出る。まだなら、またこの画面になる）。「ログアウト」は `ctx.auth.signOut()` のあと `ctx.navigate('login')`。
- `teachers.js`: 開いたら `isAdmin()` を確かめ、ちがえば設計書の文を出す。承認待ちと先生の一覧を読みこんで出す。操作のあとは読み直す。操作の最中はボタンを押せなくする（`trash.js` の `busy` と同じ）。
- 入力欄には `label` を付ける。パスワードの欄は `type="password"`、`autocomplete="new-password"`。エラーは `role="alert"`。

### 5. 練習モード（`js/dev/demo.js`）

- 最初のデータに `admins/<demo の先生の uid>: true` を入れる（今ある `teacherList` の入れ方と同じ所で）。
- 練習モードの先生の auth に `signUpTeacher(email, password)` を足す。`signInTeacher(email)` と合わせて、メールアドレスごとに別の uid になるようにする（今の demo の先生のメールアドレスは、今の uid のまま。ほかのメールアドレスは、メールアドレスから決まる uid。同じメールアドレスなら同じ uid）。パスワードは確かめず、保存しない。登録済みかどうか（`email-exists`）は、練習モードでは確かめなくてよい。
- 今ある `tests/demo.test.js` を壊さない。足した動きのテストを足す。

### 6. 規則（`docs/firebase/rules.json`、`tests/rules.test.js`）

- 設計書 3 章のとおりに足す・変える。
- テスト: JSON として読める／`admins` に `.write` が無い／`teacherList/$uid` の `.write` が `admins` を見ていて、`auth.uid !== $uid` を含む／`teacherRequests/$uid` の `.write` が `auth.provider === 'password'` と `teacherList` を見ている／`.validate` が `auth.token.email` を見ている／`teacherDirectory` を読めるのは管理者だけ／`teachers`・`sessions` の規則の文字列が変わっていない（変える前の文字列をテストに写して比べる）。
